# ennyn — design

## What this is

A development method for coding agents, packaged so any project can adopt it. The method runs in **cycles of four tasks** picked from a **work graph**: two core tasks, one **mechanization** task (turns a recurring defect class into a gate, test, type or lint), and one **legacy audit** (re-checks a finished feature). Every task follows the same protocol: read → impact table (for risky changes) → implement → test → mutation pass → bounded adversarial review → commit. Every cycle ends with a **convergence** report (how many findings were real escapes, fix-introduced, pre-existing, or caught by a gate) and a handoff.

The method was extracted from a production project where it was measured (2026-10): see `docs/evidence.md`.

## Principles (each one is a measured decision, not a preference)

1. **Answer the risky questions before writing, with commands.** Shared decision / gate / accept-reject changes get a five-row impact table (who else reads this · which other paths reach this state · what is newly accepted or rejected · what happens at the ceiling or when measurement fails · where fakes come from). Each row is answered by a command, not by the model's guess.
2. **Review is bounded.** At most two review rounds, correctness and requirements only; round two looks only at the diff of round-one fixes. A third round needs an independent signal (test, mutation run, real measurement).
3. **Lessons become mechanisms, then the prose is deleted.** A recurring defect class becomes a graph node with `mechanization: true`; one slot per cycle is reserved for it. A lesson whose rationale lives in a test is retired from instruction files.
4. **Instruction text is a budget.** Always-loaded instructions are measured in tokens and only shrink.
5. **Small batches.** The cycle ends by asking for push approval; a warning fires above a threshold of unpushed commits.
6. **Measure the loop itself.** Findings carry a class and a source when they are written; convergence, rework (SZZ-style) and review-round yield are computed by scripts, not estimated.

### Conversation style

`focused` follows the rules of i-have-adhd: the result or next action first, numbered steps, one next step, no preamble. `terse` follows the base voice of caveman, adapted for Turkish: suffixes are never trimmed, because negation lives in one (*sil* / *silme*). There is no "ultra" level. caveman's 3.1.0 release notes (10 questions, one run, length only) put its base voice 3% below a plain "Answer concisely." and its ultra level 35% below, the latter by dropping grammar; its rules cost about 1,160 input tokens per request. The gain is readability more than tokens. Both projects leave commits, code and documents alone, and so does this one: commit brevity is `commitMsg.style`, which removes prose, never grammar.

## Module contracts

All modules are ES modules, zero dependencies, JSDoc-typed, pure where possible. Functions that touch git or the file system take an explicit `cwd`.

- `core/config.mjs` — `loadConfig({ cwd, env }) → config` (defaults deep-merged; throws `ConfigError` listing every unknown key and every type mismatch, a `review.cochange` rule of the wrong shape, and every glob that does not compile).
- `core/files.mjs` — `gone(err)`: ENOENT, ENOTDIR, ELOOP or ENAMETOOLONG (nothing a name can reach). `present(path)`: false only when nothing is there; a path that cannot be looked at throws (not `throwIfNoEntry`, which on Node 20.0 hides ENOENT only). `readIfThere(path)` → text, or null for nothing there; a file that is there but cannot be read throws, its message naming the path. Used wherever "not there" would become a claim (no config, no graph, no test, a missing twin): `existsSync` answers false for a file it cannot look at.
- `core/glob.mjs` — `globToRegExp(pattern) → RegExp`, `matchAny(path, patterns) → boolean`. Supports `**`, `*`, `?` (one character, a pair of UTF-16 halves too), `{a,b}`, `[...]`. Paths use `/`; on Windows `\` is read as `/`, elsewhere it is a character of a name; a trailing `**` also matches names holding a line break or a line separator; a name matches when the pattern matches it as written, or the composed (NFC) pattern the composed name, so a decomposed name is named by a glob written composed and a combining mark after glob syntax still matches as written.

- `metrics/mutation.mjs` — `parseMutants(json) → { mutants, problems }` (a list of `{ id, file, old, new }`, every problem at once; a lone surrogate in `old` or `new` is one); `runMutants({ cwd, mutants, command, check?, journal, timeoutMs? }) → { restored, baseline, timeoutMs, results: [{ id, file, outcome, checked, reason? }] }`. The command runs first with no mutant and must exit 0, else no mutant runs; a `timeoutMs` under 1.5× that run is refused. Per mutant: `old` must occur once (overlapping occurrences count) in a UTF-8 file inside the repository (symlinks resolved), else `unapplied`; the file is checked to parse, a mutant that does not is `invalid`: JavaScript with `node --input-type=<goal> --check` on its source, the goal from the extension, else the nearest package.json `type`, else CommonJS when the original parses as such; JSON with `JSON.parse`; any other file with `check` (`{file}` replaced by the quoted path), which never replaces the built-in two. A check that fails on the original, or gives no answer (past the time limit, did not start), does not apply. Then the command: exit 0 `survived`; past the timeout (default 3× the baseline, at least +30 s, at most setTimeout's 2^31−1 ms) and again past twice that, `timeout`; else `killed`; with no check that applied, a failure or a hang is `unchecked` and a pass is `survived` with `checked: false`. A command that cannot start ends the pass (`MutationError`). It runs in its own process group, killed whole after every run, at the timeout and on SIGINT/SIGTERM/SIGHUP; the file is written back on every way out (an `exit` handler too) and each write moves its mtime to a newer whole second (caches keyed by mtime and size, Python's bytecode). `journalPath(cwd, stateDir)` is per working tree (outside a repository: a per-user directory under the temporary one); it holds the run's pid and the applied mutant's original bytes; the next run restores a file that still holds the mutant, refuses one that changed since, and refuses while the pid lives, pointing at `restoreJournal(cwd, path, { force })` (`ennyn mutate --restore --force`; without force it refuses a live pid too). The first stamp is newer than the file's mtime before the run. `summarizeMutants(results) → { killed, total, timeout, survived, invalid, unapplied, unchecked, uncheckedSurvived }`: killed (timeouts included) / total over checked mutants only.
- `metrics/convergence.mjs` — `parseConvergence(handoffText, config) → { realEscape, fixIntroduced, preExisting, gateCaught, perRound }`.
- `plan/mechanization.mjs` — `loadGraph({ cwd, config }) → { open, done }`; `readyNodes(graph, config) → node[]` (not done, gate open, every `needs` id done; best value/cost first), `readyMechanization` (the flagged ones); `pickMechanization({ open, done }, config) → node | null` (the best ready flagged node; ties by id). `graphProblems(graph, config) → [{ level, key, vars }]`: among the open nodes that are not done, which the pick reads, `fail` for a node with no id (or a blank one), an id twice (a finished node left in the open list), a need no node has, needs that wait on each other (found without recursion: a chain of any length); these four name the `source` of each item involved (`vars.where`: per id, at most three places and four ids, " · " between places; `?` for each item with no source; `×2` for a place named twice, which means the module read one item twice or two items share it; these marks before the cut; ids and places one line, at most 120 characters each), so a problem a graph module reads from the project's own files points at its lines; the same among finished nodes only is a `warn`, as are a value or cost the scales do not know, a node with no value or cost where others have one (each scored as 1), a mechanization flag that is not a boolean, and a gate that looks like "no gate" (`null`, `false`, `""`, `0`, `"false"`) but is not the open value, unless the open value is a boolean (then `false` is that project's closed value). doctor lists them; the `mechanization` command prints them and picks nothing from a graph with a `fail`. A node that is not an object, or a module graph that fails to load, is a `GraphError`; a file that cannot be read says so (not "cannot parse"); a byte order mark before the JSON is skipped (in the config and the mutant list too); each array of a module is read from its named export, else from its default export (`export default`, or `module.exports` in a CommonJS package, whose names Node detects only in part). Projects that block nodes in more ways than one gate field (the origin project has four) select in their own planner and use this only for scoring.
- `setup/scan.mjs` — `scanProject({ cwd, env }) → { repository, config, metrics, graph, handoff, fixSubject, commitStyle, churn, tests, risky, roadmap, github, pathScopedRules, agentSetup, commands, mutation }`. Read-only; a config that does not load or a path pattern that does not compile is listed in `config.problems` and the default is used; `config.loaded` is false when the config did not load, so no value in the scan is the project's. Outside a repository the history parts are empty (`repository: false`); a git that fails anywhere else stops the scan, so no part reads a failure as empty. The fix label is chosen from the last 300 commits that touch a production path (the rework rate's denominator): every pattern anchored at the subject start that matches, minus those another one covers (the more specific one on equal sets), joined into one alternation, so `fix(ui):` and `düzeltme:` are both counted; more than half matching → `majority` (the rework rate would count churn); only mentions inside subjects → `weak`, nothing proposed. `risky` lists the top-most directory named like auth, migrations, payments, ledger…, or the file itself in a flat layout; `roadmap` includes a roadmap split into a `roadmap/` directory. `agentSetup` lists what the project already has: every instruction and rule file once, with its size, when it loads (`always`, `on-demand` by path, `other` agents; a file imported with `@path`, up to five hops and inside the repository, loads like its importer) the lines that set a commit rule (`size` sums them per kind) and the lines that forbid a literal they name in a code span (`banLines`: "never", "do not", "must not", "cannot", "not permitted", "forbidden", a line that starts "No `…`", "asla", "yasak", a negative Turkish verb, an imperative such as "kullanma" only where its clause ends; outside code blocks, which end at a fence of their own character and length; at most three literals a line), skills and agents (read from disk, symlinks followed), commands, hook events from settings.json and settings.local.json, MCP servers, files that are not valid JSON (`unreadable`), and the overlaps with Ennyn by name: cycle-like skills or commands and reviewer agents. `bans` gives each ban line with the lines of the index that hold each literal (`indexMatches(cwd, texts)`: `git grep --cached -a -F -n`, 100 texts a call, each line given to every text it holds; binary files read as text (-a); each text asked for with -F as written, composed (NFC) and decomposed (NFD), `core.precomposeUnicode` off, and a line counted when it holds the text as written or composed; unlike the hook, other spellings that compose to the text (a mixed form, the Kelvin sign for "K"), a file in UTF-16 or UTF-32 and a text with letters outside ASCII in an 8-bit file are not counted; a sparse checkout counts; a file name may hold a newline; the instruction files and the config are left out; the whole index, not the line's own scope) and whether a `review.forbidden` rule already holds it; `null` outside a repository. `churn` lists paths rewritten in at least a quarter of recent commits (min. 10) that the rework rate still counts, with a generated-file marker when the file has one and the exact `excludeRe` alternative for it; paths are read with `-z`, so quotes and tabs in names survive.
- `core/style.mjs` — `styleRules(style, lang) → string | null` (`null` for `normal`). `adapters/claude-code/hooks/conversation-style.mjs` (SessionStart, `startup|resume|clear|compact`) prints it as `additionalContext`; no config or `normal` → nothing; a config that does not load (broken, or there but unreadable) → a `systemMessage` that the style was not applied; exit 0 on every path (141 when stdout is closed).
- `setup/hook.mjs` — `installHook({ cwd, cliPath }) → { result: installed | updated | unchanged | wired | other | hooksPath, path, hooksPath }` writes a commit-msg hook that runs this machine's CLI (`commit-check "$1"`) into the repository's own hooks directory (`git rev-parse --git-path hooks`, shared by linked worktrees). It leaves a hook that already runs commit-check alone (`wired`, including husky's `.husky/commit-msg` behind its `.husky/_` stubs), writes nothing when `core.hooksPath` is set (`hooksKind`: `repo`, `husky` or `global`, compared as real paths; husky is `.husky/_`, or a `_` directory holding the `h` husky writes), never overwrites another hook (`other`), and prints the shell-quoted line to add. The hook runs `commit-check --hook`: a config that does not load, a git call that fails, a moved CLI or a missing node lets the commit through with a warning that the commit was not checked; so do a config git tracks that is not in the work tree (a sparse checkout) and an `ENNYN_CONFIG` naming no file, where the defaults are not the project's rules, and an index given from outside the git dir leaves the staged paths unread, saying so. Run by hand, `commit-check` fails where the hook would let a commit through. cherry-pick, revert and autosquash folds run no commit-msg hook, so `amend!` and `squash!` text is checked when those commits are made. `hookStatus(cwd)` reads the state (a hook is `wired` only when it runs commit-check as a check, read line by line as the shell would run it: `callsCommitCheck` counts a command that names it, quoted or not, that is not text (echo, printf, `:`), not in a comment or a here-document, not after a top-level `exit`, and whose failure its line does not throw away (`|| true`, `|| :`, `|| exit 0`); a block that never runs, `if false`, is not seen), whether the file is there (`there`; husky's stub before husky installs is not) and git would run it (`runs`: executable, as git's own check), and the CLI an Ennyn hook names (`cli`). `idleReason(status)` says why a hook that runs commit-check checks nothing (`absent`, `mode`, or `cli`: no regular file at the CLI path, the hook's own `[ -f ]`); doctor and `installHook` read that one answer. `installHook` writes again an Ennyn hook that checks nothing; for one it may not write (`wired`, or Ennyn's script under `core.hooksPath`) it returns `notThere`, `notExecutable` or `cliGone` with why, and the command exits 1, as for `other` and `hooksPath`: what doctor warns about is never "nothing to do". `doctor` warns, naming them, when a rule only the hook checks is set (`commitMsg.types`, `commitMsg.style` terse, `review.forbidden`, `review.impactRequiredGlobs`, `review.cochange`, `security.secrets` unless its except holds a catch-all glob) and no hook runs commit-check, and when the hook checks nothing (`idleReason`).
- `setup/budget.mjs` — `instructionBudget(cwd, files) → { always, onDemand, listings, files, untracked, repeated: [{ line, files, everySession }], repeatedLines, repeatedEverySession }`. Tracked files only (an untracked CLAUDE.local.md or rule is this machine's and is listed in `untracked`). `always` holds the every-session instruction and rule files, what they import, and the name and description of every skill, agent and command (`listings`, YAML block descriptions included); `onDemand` the path-scoped ones. A repeat is a rule line in two or more loaded files (compared without list markers, numbering, quotes, pipes, emphasis or case; headings, code blocks and lines under 40 characters are not rules); `everySession` when a copy loads every session. `recordBudget` writes one record per commit to `paths.metricsLog` (full hash; recording again at that commit replaces the record), `previousBudget` is the newest record made at another commit, `readBudgets` counts lines that do not parse (`skipped`) and, apart, budget records with no `commit` string or no whole, non-negative size (`unusable`), instead of reading them; a record after a last line cut short starts a line of its own. `doctor` warns when the every-session bytes grew since the last record.
- `setup/doctor.mjs` — `checkSetup({ cwd, env }) → { ok, items: [{ level: ok | warn | fail | unmeasured, key, vars }], language }` (`unmeasured`: a check that could not be made, such as an unreadable hook, `.claude` file or metrics log, a file list or recent history git cannot give (a failure, or output past `git()`'s buffer), or the fix label outside a repository or with too few commits to judge; printed with `?`, counted apart, the other checks still run): git is `GIT_FLOOR` or newer (older fails, a text with no version warns; checked before the config, also outside a repository), config loads, its patterns and globs compile, the `review.cochange` and `review.forbidden` globs name tracked files, what each `review.forbidden` rule's files hold today, what the tracked CI files hold today, read together as the hook reads them (`security.ci`: tags, pull request checkouts, jobs without permissions, write-all, YAML the check cannot follow; a file it cannot read or a conflict not resolved is unmeasured; the files `except` skips are named), the graph loads and `graphProblems` finds nothing, something is ready, and the fix label is neither absent nor a majority.
