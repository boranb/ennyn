# ennyn — design

## What this is

A development method for coding agents, packaged so any project can adopt it. The method runs in **cycles of four tasks** picked from a **work graph**: two core tasks, one **mechanization** task (turns a recurring defect class into a gate, test, type or lint), and one **legacy audit** (re-checks a finished feature). Asked for one named node, or one fix (written as a node first), it runs that task alone as a cycle of its own number, with the same protocol and closing and no mechanization task or audit (`skills/cycle/one-task.md`). Every task runs in a fresh agent on a written brief and follows the same protocol: read → impact table (a core task's smallest-change row; the five rows for risky changes) → implement → test → mutation pass → bounded adversarial review → commit. Every cycle ends with a **convergence** report (how many findings were found in review, introduced by a fix, older than the loop, caught by a gate, or escaped past a commit; `skills/cycle/report-formats.md` defines each column) and a handoff.

The method was extracted from a production project where it was measured (2026-10): see `docs/evidence.md`.

## Principles (each one is a measured decision, not a preference)

1. **Answer the risky questions before writing, with commands.** Shared decision / gate / accept-reject changes get a five-row impact table (who else reads this · which other paths reach this state · what is newly accepted or rejected · what happens at the ceiling or when measurement fails · where fakes come from). Each row is answered by a command, not by the model's guess. A core task also answers a smallest-change row first: the line of the task that asks for each new piece, and what the repository, the platform, git or an installed dependency already does for it.
2. **Review is bounded.** At most two review rounds, correctness and requirements only; round two looks only at the diff of round-one fixes. After them a failing test proves a fix, not another round; `review.maxRounds` and the `Third-round:` line stay in the commit hook as the recorded exception for a project that raises the limit.
3. **Lessons become mechanisms, then the prose is deleted.** A recurring defect class becomes a graph node with `mechanization: true`; one slot of each cycle of four tasks is reserved for it (a run of one task has none). A lesson whose rationale lives in a test is retired from instruction files.
4. **Instruction text is a budget.** Always-loaded instructions are measured in tokens and only shrink.
5. **Small batches.** The cycle ends by asking for push approval, with a Claude Code ask rule as the backstop (`setup/permissions.mjs`); a warning fires above a threshold of unpushed commits.
6. **Measure the loop itself.** Findings carry a class and a source when they are written; convergence, rework (SZZ-style) and review-round yield are computed by scripts, not estimated.
7. **A failure in the commit-msg hook is weighed by what it is about, then by who can pick it.** One status read with no pathspec (`stagedNames`) tells what a commit adds or changes from what it deletes. For `security.ci`, `security.deps`, `security.secrets` and `review.forbidden` a failure refuses only when the read that failed is of what the commit adds or changes. A read of context fails as it always did, said at exit 0: tracked files the commit leaves alone, the index's listing, HEAD's version of a name, callers and callees the commit does not bring, a name the commit deletes. So a deletion never refuses, and a commit is never locked by what HEAD already holds, the one that repairs it included. The same scope holds for a name git cannot be asked for, a symbolic link and a file past 16 MB. Inside that scope a failure is said only when it is a fault of the machine (`machineFault`, by shape: any errno but E2BIG and ENOBUFS; git that ran and exited non-zero, was killed or was stopped at its limit). A commit picks no errno by name: a spawn's arguments are the only call that takes a name a commit chose, no check opens a file, and a name's length moves no git exit code (255 bytes to 1 MB, git 2.34.1 and 2.56.0 (not by a test: no record); then E2BIG, `test/core.test.mjs` "machineFault: by shape"). Anything else (E2BIG, `ERR_*`, a RangeError, any throw of our own code) is a failure the commit's own content can pick, and left to pass it is an off switch the content holds: it refuses the commit, naming the gate and what was not read (`gateFailed`, one rule at every catch), and the outer catch of each gate block refuses a throw of ours when the commit brings a file of that gate. An entry a file's mode gives to an object that is no blob is the commit's content: the secret scan asks the types first, refuses each such path by name and reads the rest (if git cannot give the types, said, the stream of added files that stops at such an object refuses the commit, and any other stop of it is said), and HEAD's version of a file it reads whole is context, so unread it is said and every hit of the staged version counts. A size is a ceiling, said, not refused, and it belongs to its file: a diff past git's 64 MB buffer leaves that file unread by `review.forbidden`, the secret scan's 64 MB budget leaves the files past it unread, and the others are judged. A list of names has no file to hold that to: the staged list reads to 256 MB, past it git is asked again without deletions (they are said), and what still does not fit is refused. "A crash blocks no commit" keeps what it was for, a fault of the tool or the machine locking every commit: a config that does not load and a git that fails still pass, saying so. A message the hook cannot read costs the message's own checks and nothing else: every gate on what the commit brings runs, no line of it approves a loosening, and that read is weighed as a gate's, so a message too long to be a string refuses. A throw of the message's shape check (a git that fails, a skipSubjects pattern that does not compile) costs the shape alone, said. Run by hand every failure throws. In cycle 17 a name past the argument limit, staged names past git's buffer, a shell function's long name and a list spread into a call each reached the old whole-gate catch at exit 0, and the first rule that refused them, by kind of failure alone, refused what the commit never brought: enumerating routes does not end, and a rule has to say what a failure is about.
8. **A task gets a fresh context.** Each task runs in a fresh agent on a written brief, not in a fork of the orchestrator's context; the orchestrator keeps the plan, the verdicts and the landing. A verification that sends a task back counts against the task, across agents, its first review round excepted: the first goes to the author, or, for a short, decided list, to a fresh agent when the orchestrator judges the author's context too large (a size it names itself, not a rule, and not the restart), the second failure restarts it once in a fresh agent on one consolidated brief, the third or later stops that task, and a landed task is closed (`skills/cycle/task-brief.md`). A host with no subagents has no fresh context, and Ennyn has not run a cycle on one.

## Project config

One file per project: `.ennyn/config.json` (override with `ENNYN_CONFIG`; `commit-check` reads it as the commit holds it, below). Unknown keys are errors. Every field has an English default; a project overrides only what differs. A path the config names (`paths.*`, `impact.ceilingRegistry`, each directory of `impact.twins`) is a config error when it holds a NUL or leads outside the project directory as POSIX or Windows reads it: absolute (`/x`, `\x`, `C:\x`, `C:x`, `\\host\x`) or climbing above it (`../x`, `a\..\..\x`). This holds for every config, whoever names it: a commit writes the project's, and one `ENNYN_CONFIG` names may be the project's under another spelling (a case, a hard link, a parent's path). `paths.stateDir` must lie under `.git/`: Ennyn trusts its state (a mutation journal names the file it restores), and no commit writes the git dir. No other path may lie in a git dir, at any depth, read in the safe direction as git reads its own paths: however a file system that ignores case, HFS+ or Windows spells `.git` (`.GIT`, `.g<U+200C>it` and the other code points HFS+ ignores, `.git.`, a stream `.git:x`, a short name `GIT~2` or `GI7EBA~1`): git reads and runs what it finds there, and a metrics log named `.git/config` or `.git/hooks/commit-msg` would be written into git's own files. A git dir of another name inside the work tree (`--separate-git-dir`) is not seen. The project's own config is read as a regular file through no link (one `ENNYN_CONFIG` names, as named). ### Conversation style

`focused` follows the rules of i-have-adhd: the result or next action first, numbered steps, one next step, no preamble. `terse` follows the base voice of caveman, adapted for Turkish: suffixes are never trimmed, because negation lives in one (*sil* / *silme*). There is no "ultra" level. caveman's 3.1.0 release notes (10 questions, one run, length only) put its base voice 3% below a plain "Answer concisely." and its ultra level 35% below, the latter by dropping grammar; its rules cost about 1,160 input tokens per request. The gain is readability more than tokens. Both projects leave commits, code and documents alone, and so does this one: commit brevity is `commitMsg.style`, which removes prose, never grammar.

## What a commit may loosen

`commit-check` reads one config for every key, `language` included: the commit's own, from the index `GIT_INDEX_FILE` names, so `git commit -a`, `git commit <path>` and an index outside the git dir read what they will commit. Run by hand no commit is being built, and an index outside the git dir is left out as a leaked environment. The work tree's config sets no gate there: an edit left unstaged, or hidden with `--skip-worktree`, loosens nothing, and the hook says when the work tree's differs. `doctor` and `ennyn deps` read the work tree on purpose: they ask what the project holds now.

Before any of this the hook checks where it stands (`hookElsewhere`). Ennyn's git calls drop `GIT_DIR` and its neighbours, so they ask what the working directory holds, while git builds the commit from what it was handed. So the working directory must be the top of the repository whose git dir is the one git says. `--work-tree`, `GIT_WORK_TREE`, `core.worktree` elsewhere, `GIT_DIR` from a subdirectory, a decoy repository as the work tree and a `GIT_COMMON_DIR` of another repository are refused in one line that names no value, before any gate. A bare repository with a separate work tree (a dotfiles setup) is refused the same way: nothing there tells it from a decoy. A plain repository hands a hook none of these variables, and a linked worktree, a submodule or a separate git dir `GIT_DIR` alone, at the top, so all of them keep working (measured on git 2.56 and 2.34.1 (not by a test: no record); `test/loosening.test.mjs` "location: a linked worktree, a submodule, a clone, a separate git dir"). A git that exits with an error refuses, a decoy's unreadable config among them, and its line says the place could not be told, in git's words, naming no cause nobody measured; one that never exits (killed, stopped, not started) is the machine's fault, said, and the commit goes through as for any such fault. A project's hook that changes folder before the check stands elsewhere too: in a linked worktree it is refused, and the block goes first (`skills/init/gates.md`). `-c core.worktree` moves nothing: git does not read that key from the command line.

A commit that loosens a gate is refused unless its message holds a body line `User-Approved-Loosening: <key>, <key>`, in one line or several, naming each key loosened. After the colon a line holds keys and separators alone, spaces, tabs and commas: any other word, or a carriage return, makes it count for nothing, so `the user refused review.forbidden` approves nothing. The line is structured, so it counts as no prose. It counts on the narrowest reading of what git may store, comment lines out (`core.commentChar` reaches a hook, set for one run too) and cut at a scissors line, since `--cleanup=` and `-v` never reach one; a line git would have kept costs moving it. It holds for every message: the bypass marker and a subject the shape check skips (`Merge`, `Revert`, `fixup!`, `squash!`, `amend!`) are read like any other. A `fixup!` is refused even with the line, since git drops its message when it folds it. In a merge a key counts when the commit is looser than every parent, so `git pull` of an approved loosening asks nothing. `MERGE_HEAD` is a file anyone can write, and what it names need not become a parent: git drops an ancestor of HEAD, and under `MERGE_MODE`'s `no-ff` keeps it and gains nothing. So a name takes a key off only as a commit that is no ancestor of HEAD (`merge-base --is-ancestor`, under the walk limit; a failure of it takes nothing off). `git merge` starts no merge of an ancestor, so an honest merge always has such a parent: a stale or forged name of an ancestor takes nothing off, with `MERGE_MODE` or without. A forged name git keeps is a real parent: its side commit is in the range, and `ennyn bypass` lists it. The cycle skill says an agent never writes the line on its own: the user says so in plain words for that key, and a task agent the hook refuses stops and reports the keys.

A list a config holds as strings holds nothing else: a member of any other kind is a config that does not load, in every list (`STRING_LISTS`), so `[null, "src/**"]` cannot read as a tighter list and then take the message check down with it.

No gate reads the rest, each listed by its full name: `language`, `conversation.style`, `commitMsg.language`, `commitMsg.fixType` (wording: it stays one of `types`), `review.agents`, and the other keys under `paths` and `graph`, `planner`, `sideCopy`, `compaction`, `context`, `impact` and `metrics`. A key added to the defaults and listed in neither place counts as loosening on any change, whatever its section, and a test fails until it is listed.

This is a tripwire and a record, not a boundary: a local hook cannot tell the user from an agent. `--no-verify`, `core.hooksPath`, a rebase, a cherry-pick and a revert skip it (`no-verify-gap`), and an amend that drops the line is compared with the commit it replaces (`hook-amend-base`). So `ennyn bypass --from <start>` reads each commit that touched the config against its first parent and lists each key loosened with its approval lines or `no approval line`: for the user, before the push. A merge lists what its first parent lacked, compared by value: a key leaves the merge only at the value a later parent holds, when a commit of the range that only that parent brings lists the key. So an approved side branch shows once, on its own commit, and any other value is the merge's own, a list included. It reads tracked paths only and takes no key from the work tree: its marker, skip list and language come from the commit at the range's end, with replace refs and grafts off, as in the hook. With a config tracked at the default place `ENNYN_CONFIG` is left out, as the hook leaves it out. With none there, what no commit holds it cannot read: an untracked or ignored config, the variable naming such a file or one outside the repository, a config that changes path in the range, a rename the hook would refuse. Each is unmeasured, by name, exit 1, and no "none" stands beside anything unread. A commit whose config entry names no blob is unread, by name, exit 1, and the rest of the range is listed.

Limits it states; the three marked friction refuse an honest commit, the others are what the hook cannot see:

- A moved config with `ENNYN_CONFIG` unset: nothing in the commit names the path, so the defaults run, silently, and a range that starts after the move shows nothing (`moved-config-unnamed`). A moved config under a name no git argument can hold is not read when the commit deletes that name: its rename compares with the defaults alone, and the hook says what it could not read.
- A project with no config at the default place, the variable set: it decides what is read, any tracked file included, and a commit cannot show that, at the hook or in the report. A project with a config at `.ennyn/config.json` is not exposed: the variable is left out there.
- A config renamed while the old file stays in the tree, the variable naming the new one: HEAD's copy is named by nothing, so the new one compares with the defaults (`moved-config-unnamed`).
- What `GIT_EDITOR` or `prepare-commit-msg` changes after git read it. An index changed after git built the tree: no commit-msg hook can see that tree; `ennyn bypass` lists the commit as unapproved (`index-after-tree`). A `.git/config` spoiled there: the hook's own git fails, so no gate runs, the hook says so in one line and the commit lands (`cli.hookGitFailed`); neither is the commit's content, `ennyn bypass` stops at the same failure, and with the file repaired lists the commit as unapproved.
- A clean filter on the config that leaves both versions unreadable: neither loads, so the hook lets the commit through and says so (`config-clean-filter`).
- An amend: git does not tell a commit-msg hook it is amending (measured: its environment is the same), so an amend that takes back that commit's own tightening is refused. Friction, never a false pass.
- A rename of a config looser than the defaults, the variable naming the new place: the defaults are part of the baseline, so a commit that changes no value needs the line. Friction, never a false pass.
- A config taken from the default place, the variable naming the new one: the commit changes no value and needs the line naming `.ennyn/config.json`. Friction, never a false pass.
- A `.git/shallow` written by hand: `merge-base --is-ancestor` goes by that file, so an ancestor cut off from HEAD reads as new and takes a key off (measured on git 2.56 and 2.34.1 (not by a test: no record)). git keeps it as a parent, no commit is brought by it, so `ennyn bypass` lists the merge. A real shallow clone needs the file, so it cannot be turned off as grafts are (`forged-shallow-ancestry`).
- A merge that keeps one parent's config whole is looser than no parent, so the hook asks nothing, even where it drops a tightening only the other parent held. `ennyn bypass` lists that merge with no approval line.
