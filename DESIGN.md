# ennyn — design

## What this is

A development method for coding agents, packaged so any project can adopt it. The method runs in **cycles of four tasks** picked from a **work graph**: two core tasks, one **mechanization** task (turns a recurring defect class into a gate, test, type or lint), and one **legacy audit** (re-checks a finished feature). Every task follows the same protocol: read → impact table (for risky changes) → implement → test → mutation pass → bounded adversarial review → commit. Every cycle ends with a **convergence** report (how many findings were real escapes, fix-introduced, pre-existing, or caught by a gate) and a handoff.

The method was extracted from a production project where it was measured (2026-10): see `docs/evidence.md`.

## Principles (each one is a measured decision, not a preference)

1. **Answer the risky questions before writing, with commands.** Shared decision / gate / accept-reject changes get a five-row impact table (who else reads this · which other paths reach this state · what is newly accepted or rejected · what happens at the ceiling or when measurement fails · where fakes come from). Each row is answered by a command, not by the model's guess.
2. **Review is bounded.** At most two review rounds, correctness and requirements only; round two looks only at the diff of round-one fixes. A third round needs an independent signal (test, mutation run, real measurement).
3. **Lessons become mechanisms, then the prose is deleted.** A recurring defect class becomes a graph node with `mechanization: true`; one slot per cycle is reserved for it. A lesson whose rationale lives in a test is retired from instruction files.
4. **Instruction text is a budget.** Always-loaded instructions are measured in tokens and only shrink.
5. **Small batches.** The cycle ends by asking for push approval; a warning fires above a threshold of unpushed commits.
6. **Measure the loop itself.** Findings carry a class and a source when they are written; convergence, rework (SZZ-style) and review-round yield are computed by scripts, not estimated.

### Conversation style

`focused` follows the rules of i-have-adhd: the result or next action first, numbered steps, one next step, no preamble. `terse` follows the base voice of caveman, adapted for Turkish: suffixes are never trimmed, because negation lives in one (*sil* / *silme*). There is no "ultra" level. caveman's 3.1.0 release notes (10 questions, one run, length only) put its base voice 3% below a plain "Answer concisely." and its ultra level 35% below, the latter by dropping grammar; its rules cost about 1,160 input tokens per request. The gain is readability more than tokens. Both projects leave commits, code and documents alone, and so does this one: commit brevity is `commitMsg.style`, which removes prose, never grammar.

## Module contracts

All modules are ES modules, zero dependencies, JSDoc-typed, pure where possible. Functions that touch git or the file system take an explicit `cwd`.

- `core/config.mjs` — `loadConfig({ cwd, env }) → config` (defaults deep-merged; throws `ConfigError` listing every unknown key and every type mismatch, a `review.cochange` rule of the wrong shape, and every glob that does not compile).
- `core/files.mjs` — `gone(err)`: ENOENT, ENOTDIR, ELOOP or ENAMETOOLONG (nothing a name can reach). `present(path)`: false only when nothing is there; a path that cannot be looked at throws (not `throwIfNoEntry`, which on Node 20.0 hides ENOENT only). `readIfThere(path)` → text, or null for nothing there; a file that is there but cannot be read throws, its message naming the path. Used wherever "not there" would become a claim (no config, no graph, no test, a missing twin): `existsSync` answers false for a file it cannot look at.
- `core/glob.mjs` — `globToRegExp(pattern) → RegExp`, `matchAny(path, patterns) → boolean`. Supports `**`, `*`, `?` (one character, a pair of UTF-16 halves too), `{a,b}`, `[...]`. Paths use `/`; on Windows `\` is read as `/`, elsewhere it is a character of a name; a trailing `**` also matches names holding a line break or a line separator; a name matches when the pattern matches it as written, or the composed (NFC) pattern the composed name, so a decomposed name is named by a glob written composed and a combining mark after glob syntax still matches as written.
- `core/encoding.mjs` — `wideEncoding(blob) → { encoding, mark } | null` (UTF-16 or UTF-32, either byte order: the byte order mark, else where the NULs are; null for a binary file), `decodeWide(blob, wide) → string`, `wideForms(text, encoding?)` (the text's UTF-16 and UTF-32 bytes, either order or one encoding's, composed and decomposed), `markLength(bytes)`, `wideLines(blob, wide, lines)`: git's added lines (split at every newline byte, also one inside another letter) as the decoded lines they are part of, numbered as an editor numbers them; `startsWithMark(bytes)`.
- `core/git.mjs` — `git(args, { cwd }) → string` via `execFileSync`; a failure throws (git's message as `stderr`, or that git was killed or not found), there is no way to read a failure as empty; `gitBytes(args, opts) → Buffer` is the same call with stdout as git wrote it. `gitMaybe(args, { cwd, env?, absent })` → stdout, or null for the exit codes in `absent` that mean "nothing there" (`config --get` 1, `rev-parse --verify -q` 1, `remote get-url` 2, `merge-base --is-ancestor` 1); any other exit, a signal or no git throws. `repoPath(flag, { cwd, env? })` → a `rev-parse` path, or null when `cwd` is in no repository, as git says it in the C locale; any other failure throws (a repository git refuses, no work tree: inside `.git` or a bare repository, a killed git). `headCommit(cwd)` → HEAD's hash, or null with no commit yet or no repository; a branch ref git cannot read (which `rev-parse --verify -q` answers like an unborn branch) throws. `test/fault-injection.test.mjs` runs every CLI command and Claude Code hook with each git call failing, then with each file read failing. Every call runs with `GIT_DIR`, `GIT_INDEX_FILE`, `GIT_WORK_TREE`, `GIT_PREFIX` removed from the environment, the variables that reshape output or pathspecs removed too (`GIT_DIFF_OPTS`, `GIT_EXTERNAL_DIFF`, `GIT_*_PATHSPECS`), literal pathspecs (`src/[id].js` names that file only), and the config that reshapes output pinned (`log.showSignature=false`, `i18n.logOutputEncoding=UTF-8`, `diff.interHunkContext=0`, `log.follow=false`, `log.showRoot=true`; `diff.algorithm=myers` and `diff.indentHeuristic=true`, git's defaults, so the rework rate is the same on every machine). The oracle test runs the readers under a global config and an environment that set these and more. A message stored as UTF-8 under a wrong `encoding` header (i18n.commitEncoding set, an editor writing UTF-8) is re-encoded by git and reads wrong; `stagedAddedLines(cwd, paths, { env? })` → for the staged paths a rule names, the lines the commit adds with their line numbers, read from the same index as `stagedPaths` with those paths as pathspecs, 500 a call (a large file elsewhere fills no buffer), every path required to show in a header (a pathspec handed back can match nothing: macOS precomposes a decomposed name, bytes that are not UTF-8 come back changed); the options that reshape a diff pinned (no color, external diff or textconv; `a/` and `b/` prefixes; a submodule as its commit line; no renames, so a moved file is added in full; `--text`, so a NUL byte, a `-diff` or `binary` attribute or `core.bigFileThreshold` hides no line); in a merge every line counts, and one a parent in MERGE_HEAD (`mergeHeads(cwd)`) already holds carries `from`, for the message only. The diff is read as bytes (`gitBytes`, `--full-index`, `core.precomposeUnicode` off so a decomposed name is asked for as git wrote it, `GIT_NO_REPLACE_OBJECTS`): a line that holds a NUL or is not UTF-8 keeps them in `raw`, and a file whose added lines hold a NUL or start with a byte order mark is read whole from the index (sizes from one `cat-file --batch-check`, bytes from `cat-file --batch`, up to `WIDE_LIMIT`, 16 MB, a file) and, when it is UTF-16 or UTF-32 text, its decoded lines are added to git's (`decoded`; `core/encoding.mjs`); a file past the limit or not read keeps git's lines, and goes into the `wideUnread` map given, with the reason. Every git call drops `GIT_TRACE*`. `addedLines(diff, asked, { complete })` parses it (a string or git's bytes), reading C-quoted names back (`unquotePath`) and throwing on a header that names a path not asked for, a staged path no header names, or a hunk header that does not parse. Output past git()'s 64 MB buffer is said as such, not as a kill; `stagedNames(cwd, { env? }) → { paths, notUtf8 }` reads the names as bytes (`notUtf8`: names git cannot be asked for, which may read like another), `stagedPaths(cwd, { env? })` its `paths` (both names of a rename; with a hook's environment it reads the index the hook was given, e.g. the temporary index of `git commit -- <path>`, but only when that index belongs to the same repository), `unpushedCount` (`null` for a detached HEAD, no upstream or an upstream never fetched; a git that fails throws), `parseTrailers`, `commonDir`, `resolveStateDir`. `GIT_FLOOR` (`"2.34"`) is the oldest git the suite runs on (`npm run test:linux`); `gitVersion({ cwd }) → { text, version }` reads `git --version` in the C locale (`version` null when the text is not git's; a git that fails throws), `parseVersion(text) → [X, Y, Z] | null` (also "git version 2.39.5 (Apple Git-154)", "2.45.1.windows.1", "2.34.0.rc1"), `versionAtLeast(a, b)` compares part by part.
- `core/i18n.mjs` — `t(key, vars, lang)`; missing key in `lang` falls back to `en`; a test asserts every `en` key exists in every catalog. A list in `vars` (`string[]`) is names, joined ", ". `tShown(key, vars, lang)` renders a report line on what the project holds, every value through `shown(value, { name })` (`UNSHOWN`: `\p{Cc}`, `\p{Cf}`, `\p{Zl}`, `\p{Zp}`, but not ZWNJ and ZWJ; on Windows a `\` alone does not quote a name). The `budget` command shows rule-file names the same way.
- `checks/commit-shape.mjs` — `checkCommitShape(message, { config, stagedPaths, cleanup, foldTarget?, alsoChanged?, addedLines? }) → { ok, errors[], warnings? }`; with `addedLines` (per staged path, the lines the commit adds) every message, one read as empty too, also gets one error per `review.forbidden` rule it breaks (`forbiddenHits(added, rules, exempt)`; `exempt`: the config's path), naming the first three places and the rule's note; `forbiddenScan(added, rules, exempt, wideUnread?) → { hits, unread }`: a line holds the text as written or composed (NFC); git's lines of a file with NULs are also searched for `wideForms` (a decoded file's own encoding only) and judged for 8-bit text, decoded or not; `unread` holds the paths a rule could not be compared in (`text`: a line that is not UTF-8 in a file with no NUL, under a text with letters outside ASCII, a leading byte order mark aside; `binary`: the same in a file with NULs; `wide`: a file not decoded, under a text with letters outside ASCII), which become warnings that say it was not checked, text files and files not decoded named, binary files counted; `warnings` come from `cochangeWarnings(staged, rules, lang, alsoChanged?)` (review.cochange) and never change `ok`. It measures the message git will store: `cleanup` is git's mode (`"whitespace"` when the hook sees `GIT_EDITOR=":"`, i.e. `-m` / `-F`, where `#` lines are kept and counted; `"strip"` for the editor; `commit.cleanup` overrides both, `"verbatim"` and `"scissors"` included; a `--cleanup=` option never reaches the hook and is not measured). `gitCuts` decides the scissors line as git does: its exact line (the first), only with `-v` / `commit.verbose` or in the scissors mode. When the editor ran with the status template (it has lines that are the comment marker alone, in any language), the template decides: a scissors line git wrote has only comment lines and the diff under it, so `-v` and `--no-verbose` on the command line are seen there; with `-m` / `-F`, `--no-status` or `commit.status=false` there is no template, `commit.verbose` decides and a flag on the command line is not seen. `hookCommitMode({ cwd, message, env }) → { cleanup, comment, cut }` is what the hook reads: commit.cleanup, the comment marker (`commentMarker`: the last of core.commentChar and core.commentString set; `auto`, in any case, from the last line git wrote into the template, else git's rule over the message) and commit.verbose, in two `git config` calls with the hook's environment (`git -c` settings included). Not seen: `GIT_EDITOR=:` set by the user while git still runs the editor path (`--amend`), and `core.commentString` on a git older than 2.45, which ignores it. `test/git-oracle.test.mjs` commits a matrix of these through real git and compares what git stores; the cells a hook cannot see are listed there with the reason. Paths matching `review.impactIgnoreGlobs` (tests, fixtures) never require the impact line.
- `side-copy/map-path.mjs` — `mapSideCopyPath(absPath, { projectDir, roots }) → { root, relPath } | null` (git worktree: same `--git-common-dir`, or, when git will not open the copy, a `.git` file whose `gitdir:` is `<common dir>/worktrees/<name>` (a submodule's `modules/<name>` is another repository); plain copy: a root under `sideCopy.roots` whose `package.json` `name` equals the project's). A path that is not there is in no side copy; a git that fails, or a directory or `package.json` that is there but cannot be read, throws.
- `adapters/claude-code/rules-index.mjs` — `loadPathScopedRules(projectDir, unreadable?) → [{ file, patterns[] }]` from `.claude/rules/**/*.md` front matter `paths:`; rule files and directories that are there but cannot be read go into `unreadable` (whether they apply is unknown), never dropped as "no rule".
- `adapters/claude-code/hooks/side-copy-rules.mjs` — PostToolUse hook: for the file tools in `FILE_TOOLS` (Read, Edit, Write, MultiEdit, NotebookEdit; the hooks.json matcher sends exactly these) on a side-copy path, emits the matching rules as `hookSpecificOutput.additionalContext`, once per rule text per context (a rule edited since it was given is given again, marked `changed`; a subagent, named by `agent_id`, has a list of its own; an id that is cleaned for a file name, holds capitals or is not text keeps a digest of the raw one), never more than `CONTEXT_CAP` (10,000) characters (`render(relPath, rules, maxBytes, lang, unreadable) → { text, given }`: a list or a note on unreadable rules too long ends in a count), marks as given only the rules the text inlines or names, and only once the text is written out, and names the rule files it could not read (they are not marked as given). The model reads this text as the harness speaking, and a side copy is no trusted tree (a worktree may hold a pull request under review): rule bodies come from the project only, never from the copy; the copy's path is always a value with a visible start and end, one JSON string in printable ASCII, every other character and `<` and `>` as `\uXXXX` (`value`: no typographic or other look-alike quote can seem to end it), and a project name (a rule file, one it could not read) is shown as it is, as Claude Code's own loading names it, or as such a value when it holds a line break, a control or format character, a quote, a backslash or an angle bracket (`named`); a name shown past `PATH_SHOWN_MAX` (the copy's path, 1,000 bytes: it shows up to three times) or `NAME_SHOWN_MAX` (a project name, 4,100: a real path shown as it is is never cut) keeps its start and its end, two JSON strings with `…` between them (cut between letters, never inside a pair of UTF-16 halves), so the text stays under the cap whatever the names and the rule that applies is at least named; a rule named only so, which cannot be opened by what is shown, is not marked as given; git runs in a copy's directory only as `rev-parse`, which runs no program the copy's config names (a test pins `core.fsmonitor`, `core.pager`, `core.editor` and `core.hooksPath`). It exits 0 on every path (never 2; 1 only when it cannot run, which includes a git that fails and a path that cannot be looked at; a closed stdout ends it with 141). `side-copy-reset.mjs` (SessionStart, `compact|clear`) forgets the session's injected lists, its subagents' too, so the rules come back after the context is compacted, and tells the user (`systemMessage`) when it could not. The error text of the three hooks is one line with every control, format and separator character escaped (`shown`): a config's key or a parse error quoting the file could otherwise drive the user's terminal. A subagent's own compaction fires no hook its list could be reset by.
- `impact/table.mjs` — `buildImpactTable({ cwd, config, symbol?, files? }) → { rows }` (five rows, S1-S5); a row that cannot be answered says `unmeasured: <reason>`, never empty, and a git call that fails is such a row, not a zero (git grep's exit 1 is "no match" only with nothing on stderr). Input paths may be absolute; they are read relative to the repository. References come from `git grep --no-color` (from the index in a sparse checkout). S3 lists the tests next to a file (named after it or importing it) and the tests elsewhere (`x.test.js`, or under a top-level `test/` directory) whose import statement names it by a relative path; an alias there may be another package's file. A row whose files are there but cannot be read is `unmeasured: <error>`, never "missing" or "no test". `formatImpactTable(table, config) → markdown`.
- `metrics/szz.mjs` — `reworkRate({ cwd, since, until, days, config, now? }) → { commits, reworked, rate, fixCommits, censored, skewed, shallow, pairs[] }`. Commits whose window has not closed by `now` are censored, not counted as clean, and so is a commit with no committer time (in a range with no dates; it is in no dated range). A strong link whose fix is dated before its origin is a wrong clock, and one whose fix has no time has no window: such an origin is no pair and, unless another fix measured it, is left out of `commits` and counted in `skewed` (only fixes dated in the range are read; with `since`, a skewed fix dated before it is not seen); `shallow` says HEAD's history has a shallow boundary. No date goes to git (its --since walk stops at a commit dated early and never reaches the commits behind it): every commit's time and hash is listed (git()'s 64 MB buffer holds some 1.2 million commits) and the bounds filter `%ct`; subjects and paths are read for the commits kept, bodies only for fix commits, each list of revisions ended by `--`. The log is read with `-z` (a quote or tab in a file name survives); blame ignores `blame.ignoreRevsFile` lists (a list naming a missing file stops git blame, and the command fails with git's error); in a shallow clone the commits at the edge (git's `shallow` file) are no line's origin; a move subject is matched as written and lowered by the commit language's rules, so `İçe aktar…` meets a lower-case pattern; write `moveSubject` in lower case. Checked against the origin project's Python measurement on the same range: September 46/306 vs 46/317, October 30/135 vs 33/141 (the denominators differ in documentation commits and author vs committer time).
- `metrics/gate-log.mjs` — `recordAttempt({ cwd, config, start, end?, exit, kind?, commit?, step?, runner? }) → { path, entry }` appends one JSON line to `<stateDir>/gate-attempts.jsonl` (files from the commit when it passed, from the index when it failed; exit 0 without a commit is a failure; contradictory input throws `RangeError` and writes nothing; a start before 2000, after the end or more than a day before it keeps the attempt with `start` and `seconds` null and the start as given in `startGiven` (microseconds and nanoseconds included); `cleanName` drops terminal escape sequences and turns other control characters into spaces in a step or runner name, at most 200 code points (a longer one ends in `…#` and 8 hex digits of its digest, so names that differ past the cut stay apart); a log that cannot be read is not appended to). `readAttempts(path) → { exists, attempts, skipped }` (no log is reported as such, not as zero attempts; a log that is there but cannot be read throws; unreadable lines are counted). The CLI refuses an option given twice, an empty `--kind`, and an empty `--commit` with `--exit 0`. `summarizeAttempts(attempts, { since?, until? })` → counts, failure rate, nearest-rank median / p90 for passing and failed attempts, time spent in failed attempts, how many attempts have no measured duration (the write rule applied to old lines too; such an attempt is placed in the window by its end), failing steps (cleaned names; ties in UTF-16 order, the same on every machine) and how many failures did not name one. Only attempts that go through the wrapper are recorded.
- `metrics/bypass.mjs` — `bypassUses({ cwd, config, since?, until?, from? }) → { commits, uses: [{ hash, time, subject, reason }], shallow }`. `from` must be an ancestor of HEAD (an amended or rebased start throws: the range would reach back past it) and present in the clone; commits merged in from another line count. `shallow` is true when a shallow clone may hold back commits of the range: without `from`, or when a boundary commit is in it. No date goes to git (its --since stops at a commit dated early); the bounds filter `%ct`, and a commit with no committer time counts only in a range with no dates. Merges count when the hook checks their first line; an amend! uses the marker in its own body only. Shares `allowMarkerReason` and `skippedSubject` with `checks/commit-shape.mjs`, so a use is what the hook let through; reads only the messages that hold the marker (`git log -F --grep`, NUL-separated). `from` is a revision (`<from>..HEAD`); an empty one is an error, a mistyped one a git error.
- `metrics/mutation.mjs` — `parseMutants(json) → { mutants, problems }` (a list of `{ id, file, old, new }`, every problem at once; a lone surrogate in `old` or `new` is one); `runMutants({ cwd, mutants, command, check?, journal, timeoutMs? }) → { restored, baseline, timeoutMs, results: [{ id, file, outcome, checked, reason? }] }`. The command runs first with no mutant and must exit 0, else no mutant runs; a `timeoutMs` under 1.5× that run is refused. Per mutant: `old` must occur once (overlapping occurrences count) in a UTF-8 file inside the repository (symlinks resolved), else `unapplied`; the file is checked to parse, a mutant that does not is `invalid`: JavaScript with `node --input-type=<goal> --check` on its source, the goal from the extension, else the nearest package.json `type`, else CommonJS when the original parses as such; JSON with `JSON.parse`; any other file with `check` (`{file}` replaced by the quoted path), which never replaces the built-in two. A check that fails on the original, or gives no answer (past the time limit, did not start), does not apply. Then the command: exit 0 `survived`; past the timeout (default 3× the baseline, at least +30 s, at most setTimeout's 2^31−1 ms) and again past twice that, `timeout`; else `killed`; with no check that applied, a failure or a hang is `unchecked` and a pass is `survived` with `checked: false`. A command that cannot start ends the pass (`MutationError`). It runs in its own process group, killed whole after every run, at the timeout and on SIGINT/SIGTERM/SIGHUP; the file is written back on every way out (an `exit` handler too) and each write moves its mtime to a newer whole second (caches keyed by mtime and size, Python's bytecode). `journalPath(cwd, stateDir)` is per working tree (outside a repository: a per-user directory under the temporary one); it holds the run's pid and the applied mutant's original bytes; the next run restores a file that still holds the mutant, refuses one that changed since, and refuses while the pid lives, pointing at `restoreJournal(cwd, path, { force })` (`ennyn mutate --restore --force`; without force it refuses a live pid too). The first stamp is newer than the file's mtime before the run. `summarizeMutants(results) → { killed, total, timeout, survived, invalid, unapplied, unchecked, uncheckedSurvived }`: killed (timeouts included) / total over checked mutants only.

- `plan/mechanization.mjs` — `loadGraph({ cwd, config }) → { open, done }`; `readyNodes(graph, config) → node[]` (not done, gate open, every `needs` id done; best value/cost first), `readyMechanization` (the flagged ones); `pickMechanization({ open, done }, config) → node | null` (the best ready flagged node; ties by id). `graphProblems(graph, config) → [{ level, key, vars }]`: among the open nodes that are not done, which the pick reads, `fail` for a node with no id (or a blank one), an id twice (a finished node left in the open list), a need no node has, needs that wait on each other (found without recursion: a chain of any length); these four name the `source` of each item involved (`vars.where`: per id, at most three places and four ids, " · " between places; `?` for each item with no source; `×2` for a place named twice, which means the module read one item twice or two items share it; these marks before the cut; ids and places one line, at most 120 characters each), so a problem a graph module reads from the project's own files points at its lines; the same among finished nodes only is a `warn`, as are a value or cost the scales do not know, a node with no value or cost where others have one (each scored as 1), a mechanization flag that is not a boolean, and a gate that looks like "no gate" (`null`, `false`, `""`, `0`, `"false"`) but is not the open value, unless the open value is a boolean (then `false` is that project's closed value). doctor lists them; the `mechanization` command prints them and picks nothing from a graph with a `fail`. A node that is not an object, or a module graph that fails to load, is a `GraphError`; a file that cannot be read says so (not "cannot parse"); a byte order mark before the JSON is skipped (in the config and the mutant list too); each array of a module is read from its named export, else from its default export (`export default`, or `module.exports` in a CommonJS package, whose names Node detects only in part). Projects that block nodes in more ways than one gate field (the origin project has four) select in their own planner and use this only for scoring.
- `setup/scan.mjs` — `scanProject({ cwd, env }) → { repository, config, metrics, graph, handoff, fixSubject, commitStyle, churn, tests, risky, roadmap, github, pathScopedRules, agentSetup, commands, mutation }`. Read-only; a config that does not load or a path pattern that does not compile is listed in `config.problems` and the default is used; `config.loaded` is false when the config did not load, so no value in the scan is the project's. Outside a repository the history parts are empty (`repository: false`); a git that fails anywhere else stops the scan, so no part reads a failure as empty. The fix label is chosen from the last 300 commits that touch a production path (the rework rate's denominator): every pattern anchored at the subject start that matches, minus those another one covers (the more specific one on equal sets), joined into one alternation, so `fix(ui):` and `düzeltme:` are both counted; more than half matching → `majority` (the rework rate would count churn); only mentions inside subjects → `weak`, nothing proposed. `risky` lists the top-most directory named like auth, migrations, payments, ledger…, or the file itself in a flat layout; `roadmap` includes a roadmap split into a `roadmap/` directory. `agentSetup` lists what the project already has: every instruction and rule file once, with its size, when it loads (`always`, `on-demand` by path, `other` agents; outside code blocks, which end at a fence of their own character and length; at most three literals a line), skills and agents (read from disk, symlinks followed), commands, hook events from settings.json and settings.local.json, MCP servers, files that are not valid JSON (`unreadable`), and the overlaps with Ennyn by name: cycle-like skills or commands and reviewer agents. `bans` gives each ban line with the lines of the index that hold each literal (`indexMatches(cwd, texts)`: `git grep --cached -a -F -n`, 100 texts a call, each line given to every text it holds; unlike the hook, other spellings that compose to the text (a mixed form, the Kelvin sign for "K"), a file in UTF-16 or UTF-32 and a text with letters outside ASCII in an 8-bit file are not counted; a sparse checkout counts; a file name may hold a newline; the instruction files and the config are left out; the whole index, not the line's own scope) and whether a `review.forbidden` rule already holds it; `null` outside a repository. `churn` lists paths rewritten in at least a quarter of recent commits (min. 10) that the rework rate still counts, with a generated-file marker when the file has one and the exact `excludeRe` alternative for it; paths are read with `-z`, so quotes and tabs in names survive.

- `setup/hook.mjs` — `installHook({ cwd, cliPath }) → { result: installed | updated | unchanged | wired | other | hooksPath, path, hooksPath }` writes a commit-msg hook that runs this machine's CLI (`commit-check "$1"`) into the repository's own hooks directory (`git rev-parse --git-path hooks`, shared by linked worktrees). It leaves a hook that already runs commit-check alone (`wired`, including husky's `.husky/commit-msg` behind its `.husky/_` stubs), writes nothing when `core.hooksPath` is set (`hooksKind`: `repo`, `husky` or `global`, compared as real paths; husky is `.husky/_`, or a `_` directory holding the `h` husky writes), never overwrites another hook (`other`), and prints the shell-quoted line to add. The hook runs `commit-check --hook`: a config that does not load, a git call that fails, a moved CLI or a missing node lets the commit through with a warning that the commit was not checked; so do a config git tracks that is not in the work tree (a sparse checkout) and an `ENNYN_CONFIG` naming no file, where the defaults are not the project's rules, and an index given from outside the git dir leaves the staged paths unread, saying so.
