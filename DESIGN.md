# ennyn — design

## What this is

A development method for coding agents, packaged so any project can adopt it. The method runs in **cycles of four tasks** picked from a **work graph**: two core tasks, one **mechanization** task (turns a recurring defect class into a gate, test, type or lint), and one **legacy audit** (re-checks a finished feature). Every task follows the same protocol: read → impact table (for risky changes) → implement → test → mutation pass → bounded adversarial review → commit. Every cycle ends with a **convergence** report (how many findings were real escapes, fix-introduced, pre-existing, or caught by a gate) and a handoff.

The method was extracted from a production project where it was measured (2026-10): see `docs/evidence.md`.

## Principles (each one is a measured decision, not a preference)

1. **Answer the risky questions before writing, with commands.** Shared decision / gate / accept-reject changes get a five-row impact table (who else reads this · which other paths reach this state · what is newly accepted or rejected · what happens at the ceiling or when measurement fails · where fakes come from). Each row is answered by a command, not by the model's guess.
2. **Review is bounded.** At most two review rounds, correctness and requirements only; round two looks only at the diff of round-one fixes. A third round needs an independent signal (test, mutation run, real measurement).
3. **Lessons become mechanisms, then the prose is deleted.** A recurring defect class becomes a graph node with `mechanization: true`; one slot per cycle is reserved for it. A lesson whose rationale lives in a test is retired from instruction files.
4. **Instruction text is a budget.** Always-loaded instructions are measured in tokens and only shrink.
5. **Small batches.** The cycle ends by asking for push approval, with a Claude Code ask rule as the backstop (`setup/permissions.mjs`); a warning fires above a threshold of unpushed commits.
6. **Measure the loop itself.** Findings carry a class and a source when they are written; convergence, rework (SZZ-style) and review-round yield are computed by scripts, not estimated.

## Project config

One file per project: `.ennyn/config.json` (override with `ENNYN_CONFIG`). Unknown keys are errors. Every field has an English default; a project overrides only what differs. A path the config names (`paths.*`, `impact.ceilingRegistry`, each directory of `impact.twins`) is a config error when it holds a NUL or leads outside the project directory as POSIX or Windows reads it: absolute (`/x`, `\x`, `C:\x`, `C:x`, `\\host\x`) or climbing above it (`../x`, `a\..\..\x`). This holds for every config, whoever names it: a commit writes the project's, and one `ENNYN_CONFIG` names may be the project's under another spelling (a case, a hard link, a parent's path). `paths.stateDir` must lie under `.git/`: Ennyn trusts its state (a mutation journal names the file it restores), and no commit writes the git dir. The project's own config is read as a regular file through no link (one `ENNYN_CONFIG` names, as named). The files Ennyn reads and writes in the project (the config, the metrics log, the graph, the ceiling registry) go through `core/files.mjs`, which follows no symbolic link below the project; doctor reads the handoff the same way, for the cycle that reads and writes it (`skills/cycle/SKILL.md` starts once doctor shows no ✗); the twins are only looked up.

### Conversation style

`focused` follows the rules of i-have-adhd: the result or next action first, numbered steps, one next step, no preamble. `terse` follows the base voice of caveman, adapted for Turkish: suffixes are never trimmed, because negation lives in one (*sil* / *silme*). There is no "ultra" level. caveman's 3.1.0 release notes (10 questions, one run, length only) put its base voice 3% below a plain "Answer concisely." and its ultra level 35% below, the latter by dropping grammar; its rules cost about 1,160 input tokens per request. The gain is readability more than tokens. Both projects leave commits, code and documents alone, and so does this one: commit brevity is `commitMsg.style`, which removes prose, never grammar.

## Module contracts

All modules are ES modules, zero dependencies, JSDoc-typed, pure where possible. Functions that touch git or the file system take an explicit `cwd`.

- `core/config.mjs` — `loadConfig({ cwd, env }) → config` (defaults deep-merged; throws `ConfigError` listing every unknown key and every type mismatch, a `review.cochange` rule of the wrong shape, and every glob that does not compile).
- `core/files.mjs` — `readRegular(root, path)` and `writeRegular(root, path, edit)`: a file read or written only as a regular file. `path` must lie inside `root` by its own spelling, and no component below `root` may be a symbolic link (each looked at with lstat, the last also opened with O_NOFOLLOW; where the flag is missing, Windows, the lstat alone stands, a window until the open); the open does not block and the descriptor must be a regular file (a FIFO, a device such as `/dev/stdin` or `/dev/zero`, a directory: refused), and the read, the rewrite or the append goes through that descriptor. A refusal names the path and why ("could not be read: … is a symbolic link", "was not written: it is no regular file") and writes nothing. The metrics log is read and written only this way (`readBudgets`, `recordBudget`, `audit`, the mark, doctor): a file Ennyn writes follows no link inside the repository, while a project file it only reads (readIfThere, through the scan's `projectFiles`) may follow a link that stays in the repository. `writeState(root, path, text, how)`, `removeState(root, path)`, `listState(root, dir)`: the state dir's files under the same rule (`append` in one write, closing a torn last line; `replace` through a temporary name that is removed, never followed, and a rename; `create` exclusive, EEXIST otherwise); the gate log, the side-copy lists and the mutation journal use only these and `readRegular`. `linkBelow(root, path, { last? })`: the first component below `root` that is a symbolic link, or null (the same walk; `undo` checks a journal's file with it). `gone(err)`: ENOENT, ENOTDIR, ELOOP or ENAMETOOLONG (nothing a name can reach). `present(path)`: false only when nothing is there; a path that cannot be looked at throws (not `throwIfNoEntry`, which on Node 20.0 hides ENOENT only). `readIfThere(path, { limit?, head?, given? })` → text, or null for nothing there; a file that is there but cannot be read throws, its message naming the path. Every pattern over a file's text runs in time linear in it (a test measures the growth). `agentSetup` lists what the project already has: every instruction and rule file once, with its size, when it loads (`always`, `on-demand` by path, `other` agents; a file imported with `@path`, up to five hops and inside the repository, loads like its importer) the lines that set a commit rule (`size` sums them per kind) and the lines that forbid a literal they name in a code span (`banLines`: "never", "do not", "must not", "cannot", "not permitted", "forbidden", a line that starts "No `…`", "asla", "yasak", a negative Turkish verb, an imperative such as "kullanma" only where its clause ends; outside code blocks, which end at a fence of their own character and length; at most three literals a line), skills and agents (read from disk, symlinks followed), commands and rule files (the side-copy hook's walk, `markdownFiles`; what it cannot read fails the scan), hook events from settings.json and settings.local.json (an event counts when one of its matchers holds a hook; an event of another shape than a list of matchers each holding a list of hooks is named in `unreadable`), MCP servers, which settings file holds an ask or deny rule for each command that leaves the machine (`ask`, `setup/permissions.mjs`; /ennyn:init proposes the missing ones), settings files the shared predicate does not count (`readSettings`: not valid JSON, over 2 MB, `hooks` or `permissions` in a shape Claude Code rejects) and a `.mcp.json` whose `mcpServers` is no object (`unreadable`), what leads out of the repository (`outside`, not read), and the overlaps with Ennyn by name: cycle-like skills or commands and reviewer agents. A literal longer than 200 characters is not offered. Code blocks are read by one reader for the ban lines and the imports (`outsideFences`: a block ends at a fence of its own character, at least its length, with nothing after it; one left open runs to the end). `bans` gives each ban line with the lines of the index that hold each literal (`indexMatches(cwd, texts)`: `git grep --cached -a -F -n`, 100 texts a call, each line given to every text it holds; binary files read as text (-a); each text asked for with -F as written, composed (NFC) and decomposed (NFD), `core.precomposeUnicode` off, and a line counted when it holds the text as written or composed; unlike the hook, other spellings that compose to the text (a mixed form, the Kelvin sign for "K"), a file in UTF-16 or UTF-32 and a text with letters outside ASCII in an 8-bit file are not counted; a sparse checkout counts; a file name may hold a newline; the instruction files and the config are left out; the whole index, not the line's own scope) and whether a `review.forbidden` rule already holds it; `null` outside a repository. `churn` lists paths rewritten in at least a quarter of recent commits (min. 10) that the rework rate still counts, with a generated-file marker when the file has one and the exact `excludeRe` alternative for it; paths are read with `-z`, so quotes and tabs in names survive.
- `core/style.mjs` — `styleRules(style, lang) → string | null` (`null` for `normal`). `adapters/claude-code/hooks/conversation-style.mjs` (SessionStart, `startup|resume|clear|compact`) prints it as `additionalContext`; no config or `normal` → nothing; a config that does not load (broken, or there but unreadable) → a `systemMessage` that the style was not applied; exit 0 on every path (141 when stdout is closed).
- `setup/hook.mjs` — `installHook({ cwd, cliPath }) → { result: installed | updated | unchanged | wired | other | hooksPath, path, hooksPath }` writes a commit-msg hook that runs this machine's CLI (`commit-check "$1"`) into the repository's own hooks directory (`git rev-parse --git-path hooks`, shared by linked worktrees). It leaves a hook that already runs commit-check alone (`wired`, including husky's `.husky/commit-msg` behind its `.husky/_` stubs), writes nothing when `core.hooksPath` is set (`hooksKind`: `repo`, `husky` or `global`, compared as real paths; husky is `.husky/_`, or a `_` directory holding the `h` husky writes), never overwrites another hook (`other`), and prints the shell-quoted line to add. The hook runs `commit-check --hook`: a config that does not load, a git call that fails, a moved CLI or a missing node lets the commit through with a warning that the commit was not checked; so do a config git tracks that is not in the work tree (a sparse checkout) and an `ENNYN_CONFIG` naming no file, where the defaults are not the project's rules, and an index given from outside the git dir leaves the staged paths unread, saying so. Run by hand, `commit-check` fails where the hook would let a commit through. cherry-pick, revert and autosquash folds run no commit-msg hook, so `amend!` and `squash!` text is checked when those commits are made. `hookStatus(cwd)` reads the state (a hook is `wired` only when it runs commit-check as a check, read line by line as the shell would run it: `callsCommitCheck` counts a command that names it, quoted or not, that is not text (echo, printf, `:`), not in a comment or a here-document, not after a top-level `exit`, and whose failure its line does not throw away (`|| true`, `|| :`, `|| exit 0`); a block that never runs (`if false`), a hook whose exit status is not commit-check's (a later command, a pipe, a background job, `|| echo`, `; true`, an `if` with no `else`, `true ||`, `!`) and a value that only names it (`MSG="commit-check is off"`) are not seen: each reads as wired, test/verdicts/hook.json holds them as gaps), whether the file is there (`there`; husky's stub before husky installs is not) and git would run it (`runs`: executable, as git's own check), and the CLI an Ennyn hook names (`cli`). `idleReason(status)` says why a hook that runs commit-check checks nothing (`absent`, `mode`, or `cli`: no regular file at the CLI path, the hook's own `[ -f ]`); doctor and `installHook` read that one answer. `installHook` writes again an Ennyn hook that checks nothing; for one it may not write (`wired`, or Ennyn's script under `core.hooksPath`) it returns `notThere`, `notExecutable` or `cliGone` with why, and the command exits 1, as for `other` and `hooksPath`: what doctor warns about is never "nothing to do". `doctor` warns, naming them, when a rule only the hook checks is set (`commitMsg.types`, `commitMsg.style` terse, `review.forbidden`, `review.impactRequiredGlobs`, `review.cochange`, `security.secrets` unless its except holds a catch-all glob) and no hook runs commit-check, and when the hook checks nothing (`idleReason`).
- `setup/budget.mjs` — `instructionBudget(cwd, files) → { always, onDemand, listings, files, untracked, outside, repeated: [{ line, files, everySession }], repeatedLines, repeatedEverySession }`. Its files are read as init-scan reads them (`projectFiles`): an instruction file or a skill, agent or command listing that leads out of the repository is not read, not counted, and named in `outside`. Tracked files only (an untracked CLAUDE.local.md or rule is this machine's and is listed in `untracked`). `always` holds the every-session instruction and rule files, what they import, and the name and description of every skill, agent and command (`listings`, YAML block descriptions included); `onDemand` the path-scoped ones. A repeat is a rule line in two or more loaded files (compared without list markers, numbering, quotes, pipes, emphasis or case; headings, code blocks and lines under 40 characters are not rules); `everySession` when a copy loads every session. `recordBudget` writes one record per commit to `paths.metricsLog` (full hash; recording again at that commit replaces the record, with what that call says: a mark only when given again; `replacedDate` is the replaced record's date, which `budget --record` says unless the record replaced is today's with the same mark (this cycle recording again), since a cycle that made no commit of its own shares the record of the cycle before; a mark replaced by a plain record is said with the coverage it drops), `previousBudget` is the newest record made at another commit, `readBudgets` counts lines that do not parse (`skipped`) and, apart, budget records with no `commit` string or no whole, non-negative size (`unusable`), instead of reading them; a record after a last line cut short starts a line of its own. `doctor` warns when the every-session bytes grew since the last record.
- `setup/permissions.mjs` — which of the project's settings files holds an ask or deny rule for each command that leaves the machine. The cycle asks the user before any push; the rule is the harness's backstop, not the gate, and the reports say what was read, not what Claude Code will do. `parseSettings(text, path)` and `readSettings(pf, path)` are the one predicate init-scan's hooks reader and the ask rules share: a file counts when it parses to an object (a byte order mark skipped, as Claude Code skips it), is at most 2 MB (`SETTINGS_LIMIT`; Claude Code skips a larger one), and holds `permissions`, `permissions.ask` and `permissions.deny` in the shape Claude Code reads; else it gives nothing and is named. A `hooks` value that is no object Claude Code drops before its check and keeps the file: it is left out and named in `dropped` (`<path> hooks`). Other keys are not checked: Ennyn does not mirror Claude Code's schema, and the doctor line says a file with any setting Claude Code rejects is skipped whole. `outwardCommands(files, github, present)`: `git push`; `npm publish` when the repository holds a package.json anywhere (a private root still publishes its workspaces), git could not list its files, or the work tree has one git does not list; with a remote on a GitHub host (`isGithubHost(urlHost(url))`: github.com, ssh.github.com, github.<domain>; every remote of `git remote -v`, `githubRemotes` in setup/scan.mjs) `gh pr merge`, `gh repo sync`, `gh release` (which also asks before `gh release view`, `list` and `download`); with none, init-scan says the gh commands were not proposed and why. `askRules(pf, commands, { committed, failed })` → `{ rules: [{ command, tool, rule, where }], unread, head }`, one entry per command and tool (`Bash`, `PowerShell`: a push through PowerShell is checked against PowerShell rules only; the PowerShell twins are not run on Windows here), `where`: `shared` (`.claude/settings.json` holds it, and so does the file as HEAD holds it), `uncommitted` (the work tree's file only: untracked, ignored or changed), `local` (`.claude/settings.local.json` only), `unknown` (a settings read that failed, a HEAD that could not be read, or HEAD holding no regular file there: `head` is `link`, `other` or `large`; never judged as missing or uncommitted), or null; HEAD is read by `headFile(cwd, path, limit)` (core/git.mjs: `ls-tree -l` of the path and each directory on its way, so a committed symbolic link is `link`, not absent; `cat-file` with no replace refs and `GIT_NO_LAZY_FETCH`, which git before 2.44 ignores, so an older git may fetch a missing object in a partial clone); an entry that is no string is skipped, as Claude Code skips a malformed rule. `ruleCovers(rule, command, tool)` counts a content rule whose one wildcard is the trailing `*` or `:*` (`Bash(git push *)`, `Bash(git push:*)`, `Bash(git *)`); a tool-wide rule (`Bash`, `Bash(*)`) is not counted, since with the sandbox on Claude Code auto-allows a sandboxed command past it, and any other form is not counted either: a missed rule is a warning, never a push read as asked about. init-scan's ask line names where each rule is and carries none of these limits; gates.md's step 3 has init say them. Where Claude Code applies the file and what a rule does not match is fixed text on doctor's line: only a session started at the repository's top (one started in a subdirectory reads that directory's `.claude/`), not when any setting in the file is rejected, not a cloud project thread or a session over several repositories; `git -C dir push`, a full path, `sh -c`, an alias, a script that pushes, `gh api` and an MCP tool are not matched. User and managed settings are not the repository's and are not read.
- `setup/doctor.mjs` — `checkSetup({ cwd, env }) → { ok, items: [{ level: ok | warn | fail | unmeasured, key, vars }], language }` (`unmeasured`: a check that could not be made, such as an unreadable hook, `.claude` file or metrics log, a file list or recent history git cannot give (a failure, or output past `git()`'s buffer), or the fix label outside a repository or with too few commits to judge; printed with `?`, counted apart, the other checks still run): git is `GIT_FLOOR` or newer (older fails, a text with no version warns; checked before the config, also outside a repository), config loads, its patterns and globs compile, the `review.cochange`, `review.forbidden` and `review.impactRequiredGlobs` globs name tracked files (an impact glob that names none is said, with the glob it likely meant when its glob syntax, read as written, names a directory: `app/[locale]/auth/**` → `app/[[]locale]/auth/**`), what each `review.forbidden` rule's files hold today, what the tracked CI files hold today, read together as the hook reads them (`security.ci`: tags, pull request checkouts, jobs without permissions, write-all, YAML the check cannot follow; a file it cannot read or a conflict not resolved is unmeasured; the files `except` skips are named), the graph loads and `graphProblems` finds nothing, something is ready, the fix label is neither absent nor a majority, and in a repository which settings file holds a rule for each of `outwardCommands` (`setup/permissions.mjs`: the committed `.claude/settings.json` is ✓ with where Claude Code applies it and what a rule does not match; missing, uncommitted or only local rules warn; a file that gives no rule, a read or git call that fails (the rules it would decide are listed as unmeasured, a remote list not read names the gh commands not checked) and a HEAD holding no regular file there are unmeasured; `askReport` takes its readers as a parameter for tests). Outside a repository the git checks are skipped; a git that fails on where the repository is stops the check. Message keys, rendered by the CLI with `tShown` (core/i18n.mjs), which shows every value on one line: one holding a control, format or line-separator character (`UNSHOWN`) is quoted and escaped as JSON with `\u` for the rest, and a name (a list in `vars`: paths, ids) is quoted also when it holds `"`, `\` or the ", " that joins the list, so no two values print alike; a quoted value takes the place of the quotes a message puts around it. The `mechanization` command prints the graph's problems the same way, and the graph's source cleaner drops the same characters.
