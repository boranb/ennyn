# Agent worktrees

Claude Code (2.1.310) puts the worktrees of agents (`isolation: worktree`), of `--worktree` and of EnterWorktree in `.claude/worktrees/<name>/` at the top of the repository's main checkout; only a WorktreeCreate hook puts them elsewhere. Each is a whole checkout holding an agent's unfinished code. Two things read it there: git, unless it ignores the folder, and every tool that walks the tree, unless the folder is on an ignore list that tool honours.

1. **git.** Doctor's agent-worktrees line says what the `.gitignore` files HEAD holds do with a worktree of any name, and what git lists or tracks there now. On a `!`, propose the line `.claude/worktrees/` in the top `.gitignore` (made when there is none) and write it on the user's yes; where the line names a negation, the new line goes after it. The line counts once it is in a commit: doctor reads HEAD, so its `!` stands until then. Say so when you ask about committing the files. When doctor says git already tracks something there, a line does not undo that: show its `git rm -r --cached` and leave it to the user.
2. **Tools.** Read the project's own scripts and hooks: what `commands` names, the package.json scripts, the Makefile, `.husky/`, pre-commit and lefthook configs, CI files (a CI job runs on a clone with no worktrees, but it shows which tools the project uses). Name each tool that walks the tree: a formatter, linter or type checker given `.`, given a glob from the top, or given no path at all. Say plainly that a tool may honour `.gitignore` or may not, and that you did not run it. Ask the user to check each one and add the folder to its ignore list where it does not. Edit no tool's config yourself.
