# Module contracts

Each module's exported functions and what they promise. Read the section of the module you touch.

## Module contracts

All modules are ES modules, zero dependencies, JSDoc-typed, pure where possible. Functions that touch git or the file system take an explicit `cwd`.

- `core/config.mjs` — `loadConfig({ cwd, env }) → config`, `configFrom(text, { cwd, configPath }) → config` (the same held to a text read from a commit or the index; defaults deep-merged; throws `ConfigError` listing every unknown key and every type mismatch, a `review.cochange` rule of the wrong shape, and every glob that does not compile).
- `core/files.mjs` — `readRegular(root, path, { limit? })` and `writeState(root, path, text, how)`: a file read or written only as a regular file; `limit` refuses a file past that many bytes (EFBIG), and the loop that counts them is `readIfThere`'s. `path` must lie inside `root` by its own spelling, and no component below `root` may be a symbolic link (each looked at with lstat, the last also opened with O_NOFOLLOW; where the flag is missing, Windows, the lstat alone stands, a window until the open); the open does not block and the descriptor must be a regular file (a FIFO, a device such as `/dev/stdin` or `/dev/zero`, a directory: refused), and the read or the write goes through that descriptor. A refusal names the path and why ("could not be read: … is a symbolic link", "was not written: it is no regular file") and writes nothing. `writeState` modes: `append` in one write, closing a torn last line, and, with `sole` (the caller alone writes the file: the metrics log), cut back to its length when the write fails and the file ends with what it put in; without `sole` (the gate log, which worktrees share) nothing is cut, as a cut could erase a line another process appended in between, and the line cut short is closed by the next append; `replace` through a temporary name that is removed, never followed, and a rename, so a write that fails leaves the file as it was and no temporary file behind; `create` exclusive, EEXIST otherwise. A write that stops short (a full disk, a file size limit) goes on from where it stopped, so the failure that follows is thrown, never a line cut short and said to be written. The metrics log is read and written only this way (`readBudgets`, `recordBudget`, `audit`, the mark, doctor): a file Ennyn writes follows no link inside the repository, while a project file it only reads (readIfThere, through the scan's `projectFiles`) may follow a link that stays in the repository. `removeState(root, path)`, `listState(root, dir)`: the state dir's files under the same rule; the gate log, the side-copy lists and the mutation journal use only these, `writeState` and `readRegular`. `linkBelow(root, path, { last? })`: the first component below `root` that is a symbolic link, or null (the same walk; `undo` checks a journal's file with it). `gone(err)`: ENOENT, ENOTDIR, ELOOP or ENAMETOOLONG (nothing a name can reach). `present(path)`: false only when nothing is there; a path that cannot be looked at throws (not `throwIfNoEntry`, which on Node 22.0 hides ENOENT only). `readIfThere(path, { limit?, head?, given? })` → text, or null for nothing there; a file that is there but cannot be read throws, its message naming the path. A file found in the project is read only when it is a regular file, /dev/null reading as empty (as Claude Code reads a file linked to it): it is looked at before it is opened, so a pipe is never opened (the open would wait for a writer) and a device never read, and the open descriptor is looked at again; a directory throws EISDIR, a pipe, socket or other device ENOTREG, a file past `limit` (`READ_LIMIT`, 16 MB) EFBIG unless `head` asks for its first `limit` bytes. A path the user named (`given`: ENNYN_CONFIG) is read whatever it is, a process substitution or /dev/stdin. Its callers and their rule: the config (`given` when ENNYN_CONFIG names it, else regular-only), MERGE_HEAD, the blame ignore list, the CLI's package.json, budget's metrics log and instruction files, init-scan's instruction, rule, settings, package.json, Makefile, roadmap files and a churn path's head (the generated-file marker), the hook files install-hook reads, and the side-copy hook's rule files (regular-only, all). Readers of their own (lock files, the impact table's source reads, mutants, a message file given to commit-check) are not behind it. Used wherever "not there" would become a claim (no config, no graph, no test, a missing twin): `existsSync` answers false for a file it cannot look at.
- `core/glob.mjs` — `globToRegExp(pattern) → RegExp`, `matchAny(path, patterns) → boolean`. Supports `**`, `*`, `?` (one character, a pair of UTF-16 halves too), `{a,b}`, `[...]`. Paths use `/`; on Windows `\` is read as `/`, elsewhere it is a character of a name; a trailing `**` also matches names holding a line break or a line separator; a name matches when the pattern matches it as written, or the composed (NFC) pattern the composed name, so a decomposed name is named by a glob written composed and a combining mark after glob syntax still matches as written. There is no escape character: `literalGlob(path)` writes a path holding glob syntax as a glob that names it alone, each `*`, `?`, `[`, `{`, `}` as a class of that one letter (`app/[locale]` → `app/[[]locale]`).
- `core/heavy-lock.mjs` — `runLocked({ command, args, limitMs, cwd?, env?, say?, room?, thresholds? }) → exit status`, `ennyn lock [--limit <minutes>] [--min-memory <%>] [--max-load <per CPU>] [--min-disk <GB>] -- <command>`: one heavy job at a time on the machine, first come first served, in the folder and layout of the hand-written `locked.sh` (`ENNYN_LOCK_DIR`, else `~/.ennyn-lock`: tickets `queue/<%017.6f seconds>-<pid>`, a ticket whose pid is gone dropped, the lock the directory `suite.lock`, taken by the first ticket), so waiters of both kinds take turns in one order. Only names of a ticket's shape (`^\d{10}\.\d{6}-\d+$`) are judged, ordered or removed; any other file in the queue is left where it is. A queue that is a symbolic link (a dangling one too) is refused before a ticket is written: the lock says so and ends with exit 1, running nothing and removing nothing. The run goes through `impact/reference-run.mjs`: its own process group, SIGTERM at the limit (default 45 minutes, at most 600), SIGKILL after `GRACE_MS`; exit 124 when the limit stopped it, 128+n for signal n, 127 for a program not found, else the command's own. A SIGINT, SIGTERM or SIGHUP to the lock goes to the runner, which stops the group the same way; a closed stdout ends the run as SIGPIPE (141). The holder writes `suite.lock.holder` beside the directory (inside it, `locked.sh`'s rmdir would fail): itself and the runner by pid and start (/proc on Linux, `ps` lstart elsewhere, so a pid given again is another process), the run's group, its deadline (limit plus grace), and the lock's inode and mtime. `deadLock(lock, holderPath, now?)` reads a lock as dead once neither process lives and the group is gone or past its deadline: any ennyn waiter then drops it, claiming the drop by renaming the record to a name of its own (one rename wins), reading it back against the lock's identity, then rmdir; a lock with no record of its own (a `locked.sh` holder's) only the first ticket drops, past 120 minutes. A drop that fails is said once and tried again a poll later. The holder sets the lock's mtime to now every minute while its run lives and rewrites the record to match, so `locked.sh` never reads a long run's lock as old (a machine asleep past 120 minutes can wake to one that reads old before the first refresh); it releases the lock only while the lock and the record are still its own, else leaves both and says so. An ennyn ticket holds its waiter's start (a pid given again is no waiter); a `locked.sh` ticket goes by its pid alone. The start's form is chosen by the platform, never by a probe, so one process never writes one form and reads another; a waiter never judges its own ticket, and one whose ticket another waiter removed ends with exit 1, saying so. A waiter reads each ticket's start once and a record's starts when its bytes change, a minute after the last read, and at every look past the record's deadline; between those it asks the pids by signal 0, so `ps` (macOS) runs do not grow with the queue. A claim that cannot be put back by link (no hard links, FAT) goes back by rename when nothing stands at the record's path, else it is left and said, never removed. A SIGKILL to the lock and its runner leaves the run's group with no limit: the lock waits for it until the deadline, then goes, and the group runs on. One JSON line a run in `lock.log` (command, cwd, waited and ran ms, end, `room`: the readings it was admitted on, `short`: what was short when it waited for room), written while the lock is held; past 1 MB the log moves to `lock.log.1`. Room: the head of the queue takes a free lock only when the machine has room, read at each poll by `readRoom({ platform?, read?, run?, load?, cpus?, free?, total?, statfs?, dirs? }) → { memory, swap, load, disk }` (each `{ value }` or `{ unmeasured: why }`) and judged by `judgeRoom(room, thresholds) → { text, short, unmeasured }`: memory free under 15% (macOS `/usr/sbin/sysctl -n kern.memorystatus_level`, the figure `memory_pressure` prints, read by its absolute path in one call with `vm.swapusage`, about 3 ms; Linux MemAvailable over MemTotal from /proc/meminfo, and in a container the smaller share its cgroup leaves: v2 `memory.max` and `memory.current`, else v1 `memory/memory.limit_in_bytes` and `memory.usage_in_bytes`, less the inactive page cache in its `memory.stat`; a v2 limit below the top of the tree the process sees is not read, a stated limit; Windows `os.freemem()` over `os.totalmem()`, which on macOS counts free pages only and is not used there), the 1-minute load over 1.5 per logical CPU of the host (`os.cpus().length`: the load average is host-wide, a container's cpuset does not narrow it; unmeasured on Windows, where `os.loadavg()` is always 0), or under 5 GB free (`fs.statfsSync`, blocks free to an unprivileged user) on the volume of the temporary folder or of the run's folder. Swap is shown and never judged: swapped pages stay out after the pressure ends, and macOS adds swap files as they fill. `roomThresholds(opts, env)` takes each from its option, else `ENNYN_LOCK_MIN_MEMORY`, `ENNYN_LOCK_MAX_LOAD`, `ENNYN_LOCK_MIN_DISK`, else the default; a value out of bounds is a usage error, and one set away from its default is said at each run. While short the job keeps its ticket first in the queue, says once what is short (value and threshold) and, once admitted, the readings; past its own limit of waiting it starts anyway and says so. A reading that cannot be made is said as unmeasured and holds nothing.
- `core/encoding.mjs` — `wideEncoding(blob) → { encoding, mark } | null` (UTF-16 or UTF-32, either byte order: the byte order mark, else where the NULs are; null for a binary file), `decodeWide(blob, wide) → string`, `wideForms(text, encoding?)` (the text's UTF-16 and UTF-32 bytes, either order or one encoding's, composed and decomposed), `markLength(bytes)`, `wideLines(blob, wide, lines)`: git's added lines (split at every newline byte, also one inside another letter) as the decoded lines they are part of, numbered as an editor numbers them; `startsWithMark(bytes)`.
- `core/git.mjs` — every call carries `FIXED_CONFIG`: what shapes parsed output, and `safe.bareRepository=explicit` and an empty `core.fsmonitor`, so a repository's own config starts nothing from a folder a clone brought in (below git 2.38 only the monitor's guard stands, and SECURITY.md names the two routes left open on 2.34.1). The refusal reaches a call started inside a real git dir too, on older gits: a failed call, which no real flow makes. `git(args, { cwd }) → string` via `execFileSync`; a failure throws (git's message as `stderr`, or that git was killed or not found), there is no way to read a failure as empty; `gitBytes(args, opts) → Buffer` is the same call with stdout as git wrote it (`buffer`: the most output, 64 MB). `machineFault(e)`: a failure no commit's content picks, by its shape (principle 7). `argBatches(paths)`: the calls names go in, 500 and 64 KiB of names a call, under the 128 KiB Linux leaves for arguments and environment on the smallest stack, a longer name alone; no path, no call. `nameText(bytes)`: a name as a string that stands for those bytes alone (a byte that fits no character a lone surrogate; `shown` prints U+FFFD), so a name that is not UTF-8 never equals a valid one. `stagedVersionsEach(cwd, paths, opts) → { versions, unaskable, failed }`: `stagedVersions` with a failure held to its name, for the caller to weigh by what the commit does to it. `gitMaybe(args, { cwd, env?, absent })` → stdout, or null for the exit codes in `absent` that mean "nothing there" (`config --get` 1, `rev-parse --verify -q` 1, `remote get-url` 2, `merge-base --is-ancestor` 1); any other exit, a signal or no git throws. `repoPath(flag, { cwd, env? })` → a `rev-parse` path, or null when `cwd` is in no repository, as git says it in the C locale (a `.git` file that points to no repository too: "not a git repository" to git 2.34 and 2.39, "gitfile does not point to a valid repository" to 2.56); `projectRoot(cwd)` → the repository's top when `cwd` is in one, else `cwd`: where the CLI and the Claude Code hooks read the config, one lookup for both; any other failure throws (a repository git refuses, no work tree: inside `.git` or a bare repository, a killed git). `headCommit(cwd)` → HEAD's hash, or null with no commit yet or no repository; a branch ref git cannot read (which `rev-parse --verify -q` answers like an unborn branch) throws. `test/fault-injection.test.mjs` runs every CLI command and Claude Code hook with each git call failing, then with each file read failing. Every git call has a time limit (`GIT_LIMITS`: 60 s, or 10 min with `walk: true` for a call that walks the history or the whole tree: `rework`'s log, blame and ancestry, `bypass`, `impact`'s grep and co-change log, `init-scan`'s search of the index, `unpushedCount`; the commit path's reads of the log are bounded and keep 60 s). Past it git is killed and its pipes closed (a process git started may still hold them), and the call fails with `git <command>: did not finish in N s and was stopped` as its message and `stderr` (code `ETIMEDOUT`, `status` null whatever git exited with), never read as "nothing there" or as an answer such as "not an ancestor"; the two streams count from git's last output (`wrote nothing for N s`), so a large commit read slowly is not stopped. git stays in Ennyn's process group, so Ctrl-C still reaches it; a process git started and did not end is left without its parent. On Windows the stop is `stopTree(pid)`: `taskkill /pid <pid> /T /F`, then `waitGone(pid, STOP_LIMIT)` (5 s of 10 ms polls of `alive(pid)`, signal 0; on Windows 10 19045 taskkill returned after its tree had exited, 20 runs of 20); a git still running then makes the message `…and was stopped, and is still running 5 s later`. git computes a file's whole diff before it writes any of it, and that time grows faster than the file (reordered short lines at load 65-75: 1 MB 5.3 s, 4 MB 50 s), so the hook's two diff readers split a commit by size (`diffGroups`, `DIFF_GROUP` 1 MB by the larger of a file's two sizes): a larger file gets a call of its own, the others go together up to 1 MB and 500 paths, and a call that fails for the machine, is stopped or passes git's buffer leaves only its own files unread, named, while the others are checked. Each slow file costs one limit: two of them (120 s) reach the 2-minute default of Claude Code's Bash tool, which ends the commit there instead of passing it. No environment variable or config sets the limits, so a committed file cannot shorten them and let a commit through unchecked; `test/fault-fs.mjs` lowers them for the fault matrix, which also hangs the first and the last git call of every command and hook. Every call runs with `GIT_DIR`, `GIT_INDEX_FILE`, `GIT_WORK_TREE`, `GIT_PREFIX` removed from the environment, the variables that reshape output or pathspecs removed too (`GIT_DIFF_OPTS`, `GIT_EXTERNAL_DIFF`, `GIT_*_PATHSPECS`), literal pathspecs (`src/[id].js` names that file only), and the config that reshapes output pinned (`log.showSignature=false`, `i18n.logOutputEncoding=UTF-8`, `diff.interHunkContext=0`, `log.follow=false`, `log.showRoot=true`; `diff.algorithm=myers` and `diff.indentHeuristic=true`, git's defaults, so neither moves the rework rate). The oracle test runs the readers under a global config and an environment that set these and more. A message stored as UTF-8 under a wrong `encoding` header (i18n.commitEncoding set, an editor writing UTF-8) is re-encoded by git and reads wrong; `stagedAddedLines(cwd, paths, { env? })` → for the staged paths a rule names, the lines the commit adds with their line numbers, read from the same index as `stagedPaths` with those paths as pathspecs, in `diffGroups`' calls, sized in a merge by every parent's version too (a large file elsewhere fills no buffer; with an `unread` map, a call that fails for the machine, is stopped or passes git's buffer puts its paths there with why, any other failure throws for the caller to weigh, a file below an asked name that was a directory at HEAD is read as what that name deleted, a path whose object `stagedChanges` finds missing is put there unasked, and a diff against a parent that fails costs only the `from` of that call's lines), every path required to show in a header (a pathspec handed back can match nothing: macOS precomposes a decomposed name, bytes that are not UTF-8 come back changed); the options that reshape a diff pinned (no color, external diff or textconv; `a/` and `b/` prefixes; a submodule as its commit line; no renames, so a moved file is added in full; `--text`, so a NUL byte, a `-diff` or `binary` attribute or `core.bigFileThreshold` hides no line); in a merge every line counts, and one a parent in MERGE_HEAD (`mergeHeads(cwd)`) already holds carries `from`, for the message only; `newParents(cwd)`, those names a merge can gain anything from: commits that are no ancestor of HEAD. `stagedVersions(cwd, paths, { env? }) → Map<path, { staged, head, unread?, headUnread?, wrongType? }>`: both versions of staged files as bytes, from the index the hook was given (`ls-files -s`) and HEAD's tree (`ls-tree`), objects as they are, `core.precomposeUnicode` off; null for a file not there; what a side cannot give is a code on that side (`symlink`, `submodule`, `large` past 16 MB, `notBlob`, `unmerged`); `notBlob` is an object this machine does not hold or one of another type, and `wrongType` names that type on the index side. An entry `git add -N` left (the empty blob, a file, a link or a submodule's mode alike) that `diff --cached` does not list is not in the commit: no staged version, no code, no `oid`. `indexNames(cwd, { env?, paths }) → { paths, notUtf8 }`: the names the index holds under `paths`, once each. `indexKinds(cwd, paths, { env? }) → Map<path, { kind: tracked | absent | symlink | submodule, link?, target?, rest? }>`: what the index holds at each path, a symbolic link (with its target) or gitlink on the way first, names compared composed and asked in both forms, `ls-files -s` 500 pathspecs a call and one `cat-file --batch` for the targets. `stagedVersions` reads blobs at most 3 × 16 MB a `cat-file` call, whatever they add up to. The diff is read as bytes (`gitBytes`, `--full-index`, `core.precomposeUnicode` off so a decomposed name is asked for as git wrote it, `GIT_NO_REPLACE_OBJECTS`): a line that holds a NUL or is not UTF-8 keeps them in `raw`, and a file whose added lines hold a NUL or start with a byte order mark is read whole from the index (sizes from one `cat-file --batch-check`, bytes from `cat-file --batch`, up to `WIDE_LIMIT`, 16 MB, a file) and, when it is UTF-16 or UTF-32 text, its decoded lines are added to git's (`decoded`; `core/encoding.mjs`); a file past the limit or not read keeps git's lines, and goes into the `wideUnread` map given, with the reason. Every git call drops `GIT_TRACE*`. The secret scan reads apart from it: `stagedChanges(cwd, { env? })` → per path the commit adds or changes its status, mode, both object ids, old and new sizes and `oldMissing` / `newMissing` (that side's object is not on this machine; a submodule's commit is none: "" and 0 on either side), from one `diff --raw` with no pathspec and one `cat-file --batch-check` (`batchCheck(cwd, oids, { env? })` → its lines, "<oid> missing" for an object not on this machine; where git dies at one instead, as the May 2024 maintenance releases do under `GIT_NO_LAZY_FETCH`, the lines before it stand and the rest is asked again; every `--batch-check` of the hook goes through it); `commit-check` puts `HOOK_READ_ENV` into its environment, so every git call it makes reads objects as they are (no replace refs, no grafts) and fetches none a partial clone lacks (`GIT_NO_LAZY_FETCH`, which git reads from 2.45 and in the May 2024 maintenance releases from 2.39.4; a git without it, 2.44.0 among them, fetches); `streamStagedDiff(cwd, paths | null, { env?, against?, onLine })` streams the same pinned -U0 diff (all staged paths with `null`, one walk of the index), calling `onLine(path, number, bytes)` for each added line and keeping nothing, and rejects with git's message when git fails; `READ_BUDGET` (64 MB) is what the scan reads of the lines a commit adds; `stagedBlobs(cwd, paths, { env?, limit?, total? })` reads staged files whole (`ls-files -s`, `cat-file`), up to 16 MB each and the budget in all, the rest in `unread` with why; `blobAt(cwd, rev, path) → Buffer | "other" | "wrongType" | null` a file as a commit's tree holds it; `hookElsewhere(cwd, env) → { elsewhere } | { untold } | null`, the location rule of "What a commit may loosen", and `HOOK_INDEX_ENV`, which `commit-check --hook` sets so that the index git names is read wherever it lies. `indexEntries(cwd) → { files, links, gitlinks }`: every name the index holds, once, its symbolic links and its gitlinks by mode (a name a conflict holds at several stages is a link when any stage is one), from one `ls-files -s`; no blob is read, so no link is followed and nothing is fetched. `addedLines(diff, asked, { complete })` parses it (a string or git's bytes), reading C-quoted names back (`unquotePath`) and throwing on a header that names a path not asked for, a staged path no header names, or a hunk header that does not parse. Output past git()'s 64 MB buffer is said as such, not as a kill; `stagedNames(cwd, { env? }) → { paths, notUtf8, deleted, added, deletedUnread }` (`added`: the names the commit adds) reads the names as bytes in one status read with no pathspec, up to `NAMES_BUFFER` (256 MB, a limit, not an allocation; `notUtf8`: names git cannot be asked for, which may read like another; `deleted`: what the commit deletes; `deletedUnread`: the list passed the buffer and was asked again without deletions), `stagedPaths(cwd, { env? })` its `paths` (both names of a rename; with a hook's environment it reads the index the hook was given, e.g. the temporary index of `git commit -- <path>`, but only when that index belongs to the same repository), `unpushedCount` (`null` for a detached HEAD, no upstream or an upstream never fetched; a git that fails throws), `parseTrailers`, `commonDir`, `resolveStateDir`, `rawChange(field) → { status, submodule } | null` (one change of `git log --raw -z`; `submodule`: neither side holds a file). `GIT_FLOOR` (`"2.34"`) is the oldest git the suite runs on (`npm run test:linux`); `gitVersion({ cwd }) → { text, version }` reads `git --version` in the C locale (`version` null when the text is not git's; a git that fails throws), `parseVersion(text) → [X, Y, Z] | null` (also "git version 2.39.5 (Apple Git-154)", "2.45.1.windows.1", "2.34.0.rc1"), `versionAtLeast(a, b)` compares part by part. `resolveStateDir(projectDir, stateDir)`: a `.git/…` value however spelled (`underGitDir`) through the common git dir, another below the project; `stateRoot(projectDir, path)`: the directory a state file is read and written below with no link (for one in the common git dir its own directory, else the project directory, else the file's own directory, such as the per-user temporary one).
- `core/i18n.mjs` — `t(key, vars, lang)`; missing key in `lang` falls back to `en`; a value carries no character `UNSHOWN` names, a line feed included (each written as a `\u` escape where it stands, so no value starts a line of its own: a config's pattern in a hook's error, a state path), and `{ shown }` text is put as its caller escaped it (a list of problems, a line each); a null value renders as `null`; a test asserts every `en` key exists in every catalog. A list in `vars` (`string[]`) is names, joined ", ". `tShown(key, vars, lang)` renders a report line on what the project holds, every value through `shown(value, { name })` (`UNSHOWN`: `\p{Cc}`, `\p{Cf}`, `\p{Zl}`, `\p{Zp}`, but not ZWNJ and ZWJ; on Windows a `\` alone does not quote a name). The `budget`, `init-scan`, `rework` and `bypass` commands show the project's names, lines and subjects the same way. A value longer than `SHOWN_MAX` (1,000) is shown by its start and end, two quoted strings with `…` between; a name holding a comma a list could be read as parted at (one with a space, a mark or a joiner after it, a comma of another script, a low quotation mark) is quoted; a value set inside a message's own quotes holding `"` or `\` is quoted and escaped, so it cannot end them; `{ shown }` passes text already shown. `unshownEscaped(text, { keepLines })` writes every character `UNSHOWN` names as a `\u` escape in place: every line the CLI writes passes it (line feeds it put there kept), and an error line escapes line feeds too, so a name in an error (a path Node or git quotes, a config key) cannot start a line of its own; a config's problems keep a line each, and a line written to stderr past 4,000 characters keeps its start and end, the cut said. `jsonShown(value)` is every command's `--json` output: JSON.stringify's, with what `UNSHOWN` names and it writes as it is (DEL, C1 controls, format characters, line and paragraph separators) as `\u` escapes; it parses to the same value. A value with no cycle is JSON.stringify's text byte for byte, an object two places share printed in each. A value with a cycle (a module graph's nodes linked both ways, a node that holds itself, a toJSON that makes a new object holding its own at each reach), which JSON.stringify alone refuses or follows without end, is found first by a walk of what JSON.stringify would print, each object once; it is then printed on one line, each object once, and every later reach of an object (a link back or a second link from anywhere) as `{ "$ref": <n> }`, n the object's number among the output's objects and arrays in the order their `{` or `[` opens in the text, the top value 0, each `$ref` object counted too (an object with a toJSON counts as itself and as what its toJSON gave, so a later reach of it is a reference to that first print even where its toJSON would give another value under another key); so its size is linear in its objects and links (a 100-node graph linked all to all: 134 KB). A data object that holds only `$ref` reads the same: a known ambiguity. toJSON runs twice on such output (the walk, then the print).
- `checks/ci.mjs` — `yamlRead(text) → { entries: [{ n, path, key, value, item, block?, unread? }], unread: [{ n, what }] }` reads YAML without a parser, in one pass with no backtracking, into entries by indentation (`item` ties the keys of one sequence item), block scalars as YAML gives their value (the raw lines in `block`), `stripComment`. It fails closed: it takes only the forms its header lists (one document with a block mapping at its root, block mappings and sequences at consistent columns, scalars on their key's line, flow collections with no properties, anchors defined once, `!!str`), exactly, and everything else is in `unread`, which the hook refuses; each refusal's `text` is the text it covers (the block it opens, the anchored node an alias names, the rest of the file, the whole file past `MAX_TEXT`), so an edit inside it is new. The forms it reads and refuses are the cells of test/reference/actions-yaml.json, each compared there with GitHub's own reading. `ciFindings(text, kind, { targeted? }) → { uses: [{ n, value, pinned, from? }], pwn, unpermitted, writeAll, unread, targeted, callees }` (`ciFindingsOf(read, kind, opts)`: the same rules on a reading already made;
