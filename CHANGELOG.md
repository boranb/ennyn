# Changelog

## Unreleased (0.0.x)

- `TRADEMARK.md`: how the name may be used (the code is MIT).
- Core: config loader (all problems reported at once), glob matcher, git helpers that never inherit a hook's repository environment, message catalogs (`en`, `tr`).
- `commit-check`: subject and body limits, structured lines, review-round rule, impact line for guarded paths. It measures the message git will store: `-m` / `-F` keep `#` lines and a scissors line, the editor drops them; a hook's temporary index is read for partial commits.
- Claude Code: side-copy rule bridge (PostToolUse) that inlines as many matching rules as fit and lists the rest; SessionStart reset after compaction or `/clear`.
- `impact`: five-row impact table, each row answered by a command or marked unmeasured.
- `rework`: SZZ strong-link rework rate (owned lines and share, sweep fixes and move commits skipped, open windows censored).
- `mechanization`, `push-check`, convergence parser and formatter.
- `bypass`: commits that used the commit-shape bypass marker, with their reasons, counted as the hook decides (reverts and merges are not uses); `--from <rev>` counts one cycle. Only messages holding the marker are read.
- `budget`: instruction text loaded in every session (with imported files and skill, agent and command descriptions) and by path, and rule lines repeated across instruction files; `--record` keeps one number per commit in `paths.metricsLog`, and `doctor` warns when the every-session text grew. Only tracked files count.
- `gate-record` / `gate-stats`: one line per commit-gate attempt in machine-local state (duration, result, files, failing step when the wrapper knows it); the summary separates "nothing recorded" from "no attempts" and counts failures without a named step as unmeasured. The origin project had to scrape its gate cost from agent transcripts, where 16% of attempts had no readable outcome.
- Method: cycle skill, finding schema, impact table guide, report formats, three reviewer agents. Their front matter is checked by a test as a YAML parser reads it (a ": " in the security reviewer's description had dropped its name and description at load).
- `/ennyn:init` (`skills/init/`): surveys the repository, asks at most six questions, writes `.ennyn/config.json`, a starting work graph and a handoff stub, then runs `doctor`. A roadmap the project already keeps in files is read by a small graph module, not copied.
- `init-scan`: fix label from the last 300 subjects (only a label at the subject start is proposed; a majority or mere mentions are flagged), paths most commits rewrite, test layouts the default `testRe` misses, risky directories, roadmap files and roadmap directories, GitHub remote, test commands (including a `scripts/validate.sh`-style gate script) and the mutation tool.
- `init-scan` reports the project's own agent setup: instruction files with size and their commit-rule lines, rules, skills, agents, commands, hooks, MCP servers, and which of them overlap with Ennyn (a cycle-like skill, reviewer agents); `/ennyn:init` asks how the cycle sits next to them; the reviewers it picks go into the new `review.agents`, which the cycle's review step reads.
- `install-hook`: commit-check as the repository's commit-msg hook (machine-local; never over another hook, never into a tracked `core.hooksPath`); `/ennyn:init` offers it, `doctor` warns when declared commit types have no hook. Ennyn's own commit rule moved from prose into this gate.
- `commit-check` skips `fixup!` subjects (autosquash folds them away whole) and checks what `amend!` and `squash!` carry into history; it reads git's comment marker (`core.commentChar` / `core.commentString`), leaves an empty message to git and accepts any spacing after the type's colon. A test keeps `|` escaped in documentation tables.
- `commit-check` follows `commit.cleanup` (strip, whitespace, verbatim, scissors) over the `-m` / editor default, and cuts at the scissors line only where git does (`-v`, `commit.verbose`, the scissors mode): a line typed by hand no longer hides the prose under it.
- A test keeps the names and home paths of projects that use Ennyn out of this repository (names as SHA-256 digests); the matching prose rule shrank to a pointer.
- `rework` (legacy audit): a file named with a quote or a tab is no longer skipped, a control character in a message cannot shift the log, and `moveSubject` matches Turkish capitals (`İ`) as well as English ones.
- The cycle reads the config, the handoff and the graph before it picks tasks; the test, lint, typecheck and mutation commands come from the handoff, and `init-scan` fills any it does not name. Without a mutation tool the cycle hand-picks mutants instead of skipping the pass.
- `test/git-oracle.test.mjs`: real git decides. A matrix of how a message is given and cleaned (-m, -F, the editor, -e; commit.cleanup; -v, commit.verbose, --no-verbose; the comment marker; commit.status; CRLF; an empty commit) must store what the commit-msg hook computes, and the log readers must read the same under a global config that reshapes git's output. It found: with `-v`, a scissors line typed above git's own was taken for a hand-typed one and the prose under it counted; `--no-verbose` lost to `commit.verbose`; `core.commentChar=auto` read a typed scissors line as git's; `i18n.logOutputEncoding` garbled non-ASCII subjects (a `düzeltme:` fix label never matched); `diff.interHunkContext` and `GIT_DIFF_OPTS` shifted the lines the rework rate blames. Review added more of the same class, now fixed and in the matrix: `--no-status`, a scissors line typed under git's own, `core.commentChar=AUTO`, the last of commentChar and commentString winning, a translated template; for the readers, a file name that is a glob (`src/[id].js`), `blame.ignoreRevsFile`, `log.showRoot` and `log.follow`, the diff algorithm, the edge of a shallow clone (blamed for every older line), and a quoted path in an `amend!` target. The hook now reads its config in two git calls instead of five.
- A test keeps README.md and README.tr.md the same in what a translation does not change: headings and their levels, and per section the list items, quotes, bold claims, table rows with the code in each cell, code blocks, code spans, link targets and numbers (0.5 = 0,5, %66 = 66%). The matching prose rule left .claude/CLAUDE.md.
- `impact` (legacy audit): with `color.ui=always` the references were read with escape codes (line numbers NaN, the input file counted as its own reader); a git grep or log that failed read as "no references" or "no co-change", and a failing `ls-files` stopped the table; a test in a top-level `test/` directory was not seen; an absolute `--files` path gave a wrong table; a sparse checkout hid readers. Each is now measured or says unmeasured.
- `npm test` loads a hostile machine into every test file (a user and system git config, XDG and ignore files, GIT_* variables, `ENNYN_CONFIG`, a temporary directory inside a repository, a far time zone and a Turkish locale, each with a value that broke a test before), then a setup that clears it: a test that reads the user's setup fails on every run, not on someone else's machine. 85 tests failed this way before. A child process given an environment without the setup's `GIT_CONFIG_NOSYSTEM` is refused where the test starts it. The suite runs on Node 20 again.
- `mutate`: runs a JSON list of hand-picked mutants one at a time against the test command, after the tests pass with none. A mutant that does not parse is invalid, never killed: JavaScript is checked as Node reads it (module or CommonJS), JSON with `JSON.parse`, other files with `--check` (it never judges JavaScript or JSON). Killed / total counts only mutants a check read; in a file none reads, failures and passes are counted apart. A mutant still running at the timeout, and again at twice that, is killed with every process its tests started; processes a test run leaves behind are stopped after it; a test run that cannot start ends the pass; a timeout the tests cannot meet is refused. Each file is written back byte for byte with a newer mtime, also after a signal or a closed output pipe, and a run killed outright is undone by the next one or by `mutate --restore` while the file still holds the mutant (`--force` when the journal's pid now belongs to another process). The cycle's mutation pass uses it when the project has no mutation tool.
- `review.cochange`: documents tied to code paths; `commit-check` warns, without failing, when a staged path changes and none of its documents does. Ennyn's own config ties the two READMEs to each other, the modules to DESIGN.md, the English messages to the Turkish ones and user-visible code to CHANGELOG.md; the README rule left .claude/CLAUDE.md. Both names of a renamed file now count as staged, so moving a file out of an `impactRequiredGlobs` path needs an Impact line too; a glob that does not compile, in any glob key, is a config problem at load.
- `bypass` (legacy audit): a `--from` that history no longer holds (an amended or rebased cycle start) fails instead of counting commits from before it; one past a shallow clone's boundary is named, and a shallow clone says its count may stop at the boundary. A commit dated days early no longer hides the newer ones from `--since`; a merge with a subject of its own, which the hook checks, counts; an amend! repeating its target's subject is not a second use. The range is listed by commit time alone, a fifth of the output on a long history.
- `rework`: a commit dated days early no longer hides the commits behind it. No date goes to git; the bounds filter commit time, and subjects and paths are read only for the commits in range and their fixes. A fix dated before the commit it repairs, a shallow clone and a commit with no committer time are said, not counted as clean; a file named like a commit's hash no longer stops git (also in `gate-record` and in the hook's `amend!` / `squash!` target).
- The suite runs on the oldest Node that `engines` allows: a CI workflow runs `npm test` on Node 20.0.0, 22 and 24, and a test keeps its first entry equal to the floor in package.json, the lock file and both READMEs. Measured on the way: Node before 20.11 loads two `--import` modules at once, so under load the hostile machine was set up after the setup that clears it (15 of 60 starts on 20.6 and 20.10); `hermetic.mjs` now imports `hostile.mjs` and `npm test` gives one `--import`. On Linux, `mutate` made the state dir of a repository under `/tmp` private (0700). A per-user journal directory that another user could have made or can write to, and a journal that names a file outside the tree, are refused before anything is restored. The test holds the workflow's whole text, so no condition or override can skip the floor; tests that a killed process is gone wait for it to be reaped.
- Every CLI command runs in a test with each of its git calls failing, then killed, then with no git at all (`test/fault-injection.test.mjs`): it must fail, print what it prints without the fault, or say on each changed line that it could not measure; a closed stdout must end it without a stack trace. The first run found 44 cells that read a failed git call as "nothing there": `budget` and `doctor` reported 0.0 KB of instructions, `init-scan` and `doctor` 0 commits and 0 test files, `rework --json` and `bypass` no commits. A failed git call now throws; where git answers "nothing there" with an exit code of its own (an unset key, a missing ref, no repository), `gitMaybe` and `repoPath` read that code and nothing else, and `allowFail` is gone. A repository git refuses, a broken branch ref and a working directory inside `.git` are errors, not "outside a repository" or "no commits"; a tracked file that cannot be read is no empty file. A closed stdout ends a command with 141, as SIGPIPE does: a run cut short is no pass. The commit-msg hook lets the commit through when git fails, saying the message was not checked, and says so too when an `amend!` / `squash!` target is not in the last 500 commits or past a shallow boundary. Outside a repository `doctor` runs its other checks and calls the fix label unmeasured.
- `doctor`: config loads, patterns compile, graph ids are unique and `needs` exist, something is ready, the fix label separates repairs.
- Commit convention: `commitMsg.language` (commit text, can differ from `language`), `commitMsg.types` (enforced by `commit-check`) and `commitMsg.fixType` (the one type for repairs). `/ennyn:init` offers them from the history's language and types and replaces a conflicting commit rule in the project's instructions on the user's yes; `doctor` warns when `metrics.fixSubject` misses the fix type.
- Voice: `conversation.style` (`normal`, `focused`, `terse`; rules in `styles/`, injected by a SessionStart hook in the config language) and `commitMsg.style` (`terse`: no prose body). Numbers, paths, commands, negations and money or data-loss warnings are never shortened; the conversation style never touches files or commits.
- A config whose root is not an object, a graph node that is not an object and a module graph that fails to load are reported as config or graph errors.
