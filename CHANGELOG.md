# Changelog

## Unreleased

- Under `push.mode: after-closing` the push hook lets a bare `git push` run only on push-check's own verdict (`pushVerdict` in `checks/push-mode.mjs`, which `push-check` now prints): the commits rule on what the push sends and a green test run recorded on the pushed tree, read without a fetch; anything that fails or takes longer than 5 s asks. A bare push with nothing to send is asked.
- The push hook refuses a push written in a subagent (the hook input's `agent_id`) instead of asking it, in either push mode, since Claude Code routes a subagent's ask to the session's prompt, where an unattended run waits; the refusal names the fetch form a lab's upstream takes. SECURITY.md states that a hook which crashes or times out there leaves the push to the ask rule. The verdict corpus gains a `push` gate.
- `security.privateText.listExpected` (off by default): a project says it keeps a private word list; with it on, a clone with none (or an empty one) is told on every commit, by commit-check, that no listed word was checked and how to get a list, and doctor warns; never refused. Turning it off is a loosening. Ennyn's own config turns it on.
- install-hook run through npx (no install) refuses to write a hook naming npm's npx cache and names the plugin or a clone; doctor warns for such a hook already written.
- The push hook's verdict starts no OpenPGP or x509 signature verifier and fetches nothing in a partial clone on any git version; in a subagent a refused push spelling gives the lab's fetch form; `push-check` prints the lines it holds when a later step fails; doctor's after-closing line says what it leaves to the push.
- Tests: the engines test holds the npm package whole: `bin` names a file with a node shebang, every module the CLI and the hooks import (static, literal dynamic and `new URL` reads, in any quotes) and the folders read by built paths ship under `files`, no ignore file inside a shipped folder drops one, and the lock names the package's version.

## 0.1.1 (2026-11-23)

- Ennyn is published to npm as `ennyn`. A version tag starts `.github/workflows/release.yml`, which waits for the owner to approve it in the `npm` environment and publishes with npm trusted publishing: no npm token is stored, and npm attaches the provenance attestation.
- The plugin description now also names the kill refusal the hooks apply, and the READMEs link to install from the top.
- A node that holds `[NEEDS CLARIFICATION: <question>]` in any of its strings is never picked: `core` and `mechanization` name it with its question, and doctor warns. A node made from a request names it in `source` only as `the user, <date>: a request` (or `approved`, `left to the session`); the sentence a brief needs stays under the state dir, and the closing reads the host's memory notes changed during the cycle.
- `ennyn audit` counts the security audits recorded before the history rewrite again: their coverage keys follow the rewritten metrics lines.
- `commits.addresses` and `commits.signed` (unset by default): `push-check` holds a push to the strictest `commits` block of the work tree's, HEAD's and the upstream's config, and refuses, in every mode, a commit by an address outside the list or, with signing asked, one that is not SSH-signed and verified for a key the clone's allowed-signers file lists for its committer; a push that git config makes send more refs than HEAD's branch, or to a url other than the one its upstream is fetched from, is refused as unmeasured. `doctor` names missing clone settings and an unlisted signing key; the new `ennyn clone-setup` prints the per-clone settings and builds the allowed-signers file from the SSH signing keys GitHub lists for a login.
- commit-check refuses private text (`security.privateText`): a word of the clone's private list (`ennyn private-text add`, kept hashed in the state dir), a home path, an address `commits.addresses` does not hold and conversation shapes, in added lines, added names and the message as git stores it; and a graph source that names the user outside `the user, <YYYY-MM-DD>: a request`. `home` and `conversation` are opt-in; each place is named with the rule and a length, never the text.
- `core --json` and `mechanization --json` carry `held: [{ id, question }]`, the slot's nodes a clarification marker holds, always present; `mechanization --json` is an object even when nothing is ready (`node` null). A near spelling of the marker (any case, full-width forms, the Turkish İ and ı) holds a node too and doctor names it; a module graph's node no longer holds the marker of another node it links to. Every `--json` output prints a value with a cycle on one line, each object once and every later reach as `{"$ref": n}` (n its number in the order the text opens objects and arrays), so its size is linear in its objects and links; a value with no cycle prints as before.
- The cycle's task brief says a lab never writes `git push` in a shell command, even into a local bare repository (a push ask rule reads the text and waits with nobody there), and sets its upstream with fetch; a reviewer's brief carries it too.
- `ennyn clone-setup` now quotes the fill-in it prints when no signing key is set, so its lines paste into sh as printed. A new test parses every shell text Ennyn builds (the hooks, the printed block, line and chmod, the env-file line, clone-setup's commands, scan's mutation command, the impact table's commands) under sh, dash and bash, checks that no value expands, and reads the pasted lines back word by word.
